# 질리카 전용 분 단위 감시

사용자 요청에 따른 운영 추가. 기준 소스: main 8b636f12af461856b713f5a4614174e87f0a7f8f.

- 기존 업비트 프로세스의 독립 asyncio 작업. 공개 REST 원본 봉을 매분 경계 +3초에 확인한다. 틱 실시간 예비 경보는 구현 범위가 아니다.
- KRW-ZIL만 확인. 기존 전 종목 후보 조건·LBank 운영에는 변경 없음.
- 완료 1분 거래량 / 직전 20개 완료봉 중앙값 >=5, 거래대금 >=1000만원 또는 완료 5분 거래량 >=3배, 거래대금 >=3000만원.
- 상승·하락·보합 급증 모두 관찰 알림. 저유동성으로 기준 20봉이 긴 시간을 차지하면 표시. 0 기준과 미완성 봉은 배율 판정에서 제외.
- 신호 발생 때만 현재가·1시간 추세·호가 추가 조회. 가까운 과거 관측 고저가를 지지·저항 참고로 표시하며, 인위적인 수익 목표나 매수 지시를 만들지 않는다.
- 기존 Telegram 발송 및 영속 감사 장부 사용. 이벤트 ID(시장/주기/봉시각)별 API 응답 성공 후 저장. 재시작 시 같은 봉의 재발송 억제. 응답 유실 또는 응답 직후 저장 전 종료 시 중복 가능성은 남는다.
- 최근 180초 이내 종료 봉만 처리. 긴 장애 구간은 뒤늦은 알림으로 재생하지 않으며 오류 로그로 구분한다.
- 추가 REST 호출은 정상 시 분당 2회. 기존 공용 속도 제한 사용.
- `ZIL_WATCH_ENABLED=false`로 중단. 기본 종료는 공식 공지에 따른 2026-11-16 15:00 KST. 일정 변경 확인 후 시간대 포함 `ZIL_WATCH_END_AT` 설정 가능.
- 영속 감사 장부가 없으면 전용 감시는 시작하지 않는다. `ZIL_WATCH_STARTED`, `ZIL_WATCH_TICK`, `ZIL_WATCH_DELIVERED`, `ZIL_WATCH_ERROR`, `ZIL_WATCH_EXPIRED` 로그와 MCP `get_monitor_status`의 `config.zil_watch`로 확인한다.

검증: tests/test_zil_watch.py, tests/test_monitor.py, tests/test_minute_surge.py, tests/test_upbit_client.py 합계 175개 통과. 상승/하락/보합, 완료/미완료, 저유동성, 최소 거래대금, 재시작 중복, 발송 실패 재시도, 거래종료, 오래된 현재가 차단 포함. 이는 동작 검증이며 수익성 검증이 아니다.
