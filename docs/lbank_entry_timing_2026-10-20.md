## 일정 재현 및 회귀 검사

실제 기준/수정 `run()`에 같은 시계를 주입했다. 0초에는 원본 준비 안 됨, 15초에 원본이 준비되고 심사가 통과하는 통제 사례다. 외부 연결, 조건 판정 반환값과 전송은 모의 객체다.

| 단계 | 기존 | 수정 |
|---|---:|---:|
| 후보 평가 | 60초 | 15초 |
| 최소 확인 후 모의 발신 | 90초 | 45초 |
| 원래 가격 표본 저장 | 0·60초 | 0·60초 |

이 사례의 45초 단축은 매 알람의 단축 보장이나 시장 수익률이 아니다. 원본 공백·기록 실패 시 진입 차단, 중복 발신 방지, 위험 처리 우선, 기존 0.10% 제한과 실제 native 심사, 일정 기록의 보존, 과거 재생의 원본 공백 차단을 검사했다. 구현 테스트 336개가 통과했다. 성과 검증 336건이라는 뜻은 아니다.

## 사건 자료 재현과 한계

현재 도구 경로는 Railway 런타임 SQLite를 직접 읽는 셸을 제공하지 않는다. 실제 코드 배포에 포함된 별도 진단 데몬이 최근 발신 1건의 공개 봉·관측가·판정 기록만 읽기 전용으로 캡처한다. 최대 800개 봉/120개 관측가이며, 거래소 계정·주문·신고 포지션·인증정보를 읽거나 내보내지 않는다. 진단 실패는 감시를 중단하지 않는다. 연구 문서 저장을 위한 별도 재시작은 하지 않는다.

과거 실제 봉 공개 시각과 모든 tick이 없으므로 **관측가가 저장된 시점들에서만** 최초 동일 전략·방향 심사 통과를 재계산한다. 실제 최초 가능 시각, 더 이른 실제 발신, 과거 쿨다운 통과, 수동 체결 및 수익을 증명하지 않는다. 원본 공백은 보간하지 않고 해당 시점 재현을 실패 처리한다. 실제 발신의 후보 가격·원본봉 키가 보존된 판정과 맞으면 확인 시점의 같은 규칙·손절·목표를 재계산해 대조한다. 압축 원본에 SHA-256을 붙여 로그에서 복원하고 동일 계산을 다시 실행할 수 있다.

```bash
PYTHONPATH=. python research/replay_entry_incident.py --railway-log <bounded-log.json> --save-bundle <incident.json> --output <result.json>
PYTHONPATH=. python research/replay_entry_incident.py --bundle <incident.json> --output <result-again.json>
```
