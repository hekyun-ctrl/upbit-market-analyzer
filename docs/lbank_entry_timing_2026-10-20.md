## 추가 확인 일관성 제약

정책 `native_breakout_trigger_or_higher_priority_v1`은 #13을 개발 사례로 삼아 정의한 보수적 발신 제약이다. 최초 돌파 후보와 발신 시점의 근거를 같은 원래 식으로 대조한다. 신규 지표·점수·최적화 숫자를 넣지 않는다.

1. 모든 기존 확인·구조·RSI·비용·위험·위치 심사를 먼저 통과해야 한다.
2. 현재 완료봉에도 원래 동일 방향 돌파 조건(이전 15개 분봉의 고저, MACD, 기존 5분/15분 변화율 0.14%/0.20%)이 성립하면 기존처럼 허용한다.
3. 원래 돌파 조건이 사라졌다면 **기존** 상위 구조 우선권(`dominant_intact` 또는 `may_override_minor_reaction`)이 실제로 충족돼야 한다. 상위 방향이 확실하면 작은 되돌림만으로 취소하지 않는다. 위험·원래 손절·반복 장벽·확장 제한을 이 우선권으로 새로 우회하지 않는다.
4. 돌파와 기존 상위 우선권이 둘 다 없으면 `breakout_trigger_lost_without_higher_priority`로 해당 후보를 취소한다. 더 긴 확인 대기에 보관했다가 발신하지 않는다. 이후 새 후보는 기존 최초 심사를 다시 통과해야 한다. 이미 발신한 신호의 위험 경고는 숨기거나 바꾸지 않는다.

단순히 돌파가 유지됐다는 이유만으로 약해진 후보를 내보내던 경로를 제한하는 변경이다. **#13의 차단은 개발 사례 재현이며 독립 성과 검증이 아니다.** 이 제약으로 수익성·승률·빈도 개선을 입증한 것은 아니다. 반등 후 유효한 재개도 일부 제외할 수 있으며, 추가 대기 시간은 없지만 발신 수가 줄 수 있다. 이를 수익성 있는 대체 전략의 승격으로 표시하지 않는다.

## 사건 자료 재현과 한계

현재 도구 경로는 Railway 런타임 SQLite를 직접 읽는 셸을 제공하지 않는다. 실제 코드 배포에 포함된 별도 진단 데몬이 최근 발신 1건의 공개 봉·관측가·판정 기록만 읽기 전용으로 캡처한다. 최대 800개 봉/120개 관측가이며, 거래소 계정·주문·신고 포지션·인증정보를 읽거나 내보내지 않는다. 진단 실패는 감시를 중단하지 않는다. 연구 문서 저장을 위한 별도 재시작은 하지 않는다.

과거 실제 봉 공개 시각과 모든 tick이 없으므로 **관측가가 저장된 시점들에서만** 최초 동일 전략·방향 심사 통과를 재계산한다. 실제 최초 가능 시각, 더 이른 실제 발신, 과거 쿨다운 통과, 수동 체결 및 수익을 증명하지 않는다. 원본 공백은 보간하지 않고 해당 시점 재현을 실패 처리한다. 실제 발신의 후보 가격·원본봉 키가 보존된 판정과 맞으면 확인 시점의 같은 규칙·손절·목표를 재계산해 대조한다. 압축 원본에 SHA-256을 붙여 로그에서 복원하고 동일 계산을 다시 실행할 수 있다.
