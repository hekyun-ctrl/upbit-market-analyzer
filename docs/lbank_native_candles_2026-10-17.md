# LBank 원본 선물 봉 수집 경로 확인

> 아래는 초기 수집기 배포 당시 기록입니다. 이후 실전 알람 연결 변경은 [원본 봉 알람 연결 문서](lbank_native_entry_2026-10-17.md)를 참조하세요.

2026-10-17 조사. 공개 웹 차트가 사용하는 WebSocket에 로그인·거래 API 키 없이 연결하여 BTCUSDT 선물 5분봉 스냅샷과 1분봉 갱신을 실제 수신했다. 기존 ticker 표본만으로는 알 수 없던 시가·고가·저가·종가·거래량·거래대금을 받는 경로다.

## 확인된 원인

설치된 CCXT 4.5.88의 LBank `fetch_ohlcv` 구현은 `spotPublicGetKline`을 호출한다. `defaultType=swap` 설정만으로 이 경로가 선물 봉 API로 바뀌지 않는다. 현물 데이터를 선물 데이터로 표시해서는 안 된다.

공식 Contract API 문서에서 봉 경로를 찾지 못했다는 사실을 선물 원본 봉 자체가 존재하지 않는다는 뜻으로 확대해서는 안 된다. 이번에는 공식 웹 클라이언트의 별도 수신 경로를 확인했다.

## 실제 수신 경로와 형식

- 공개 선물 화면: `https://www.lbank.com/futures/btcusdt`
- 해당 화면의 운영 WebSocket: `wss://uuws.rerrkvifj.com/ws/v3`
- 공개 구독 메시지: `{"x":2,"y":"2000000001","z":1,"a":{"i":"BTCUSDT_5m"},"e":"{\"bvc\":\"202\",\"isUsd\":1}"}`
- `x=2`는 봉 채널, `z=3`은 초기 응답, `z=4`는 갱신이다.
- 초기 응답의 `b=5m`과 이후 갱신의 `b=1m`을 실제 확인했다. 1분봉 갱신을 5분봉으로 오인하면 안 된다.
- 봉 필드: `a` 심볼, `b` 주기, `c` 봉 시작 시각(Unix 초), `d` 시가, `e` 종가, `f` 고가, `g` 저가, `h` 거래량, `i` 거래대금, `k` 갱신 시각. 외부 프레임의 `w`는 서버 시각(밀리초)이다.
- `BTCUSDT`는 마지막 거래가격 봉이다. 웹 차트는 표시 기준에 따라 `mBTCUSDT`(표시가격)·`iBTCUSDT`(지수가격)를 별도로 사용한다. 이번 수집은 이 접두사가 있는 데이터를 거절한다.
- 종목 정보의 계약 단위와 사용자 차트의 거래량 표시 단위 변환은 아직 별도 대조하지 않았다. 거래량은 원본 필드 단위로 보존한다.

실제 초기 응답 예: 시작 시각 `1792209600`, 시가 `81532.5`, 고가 `81532.5`, 저가 `81518.6`, 종가 `81518.6`, 거래량 `0.3646`. 당시 진행 중인 봉이며 확정 봉이나 현재 가격으로 인용하면 안 된다.

## 구현 범위

`lbank_native_candles.py`를 기존 서비스의 독립 수집 스레드로 연결했다. 이 코드는 주문을 전송하지 않으며 기존 진입 알림의 데이터 소스를 변경하지 않는다.

1. 원본 5분 스냅샷은 진행 중 자료로만 저장한다.
2. 후속 원본 1분봉 갱신은 동일 봉을 덮어쓴다. 누적 거래량을 매번 더하지 않는다.
3. 동일 연결에서 다음 1분봉이 도착하고 직전 수신 간격이 15초 이내이면 이전 봉을 `stream_closed`로 기록한다. 이는 스트림 진행으로 추정한 마감이며 REST 확정 플래그로 검증한 마감이 아니다.
4. 연속된 1분봉 다섯 개가 모두 마감된 경우에만 5분 OHLCV를 구성한다. 빠진 봉은 보간하지 않는다. 연결 끊김·재시작 때 진행 중이던 봉은 공백으로 분리한다.
5. SQLite에 14일 동안 저장하며, 오류 시 2~60초 간격으로 재연결한다. 공개 웹 프로토콜은 사전 통지 없이 바뀔 수 있다.
6. 최근 확정 추정 5분봉 250개가 끊김 없이 모이면 Wilder RSI(14)를 별도 검증 로그에 계산한다. 250개는 초기화 영향 감소를 위한 검증용 준비 기준이며 매매 조건이 아니다. 전부 새로 쌓는 데 최소 약 20시간 50분이 필요하고 끊김이 있으면 더 걸린다.

## 아직 해결되지 않은 부분

웹 클라이언트에서 과거 봉 경로 `GET /cfd/query/v1.0/KLinelst`와 파라미터(`instrumentID`, `exchangeID`, `startDatetime`, `count`, `type`, `isUsd`)를 확인했다. 하지만 확인한 두 공개 호스트에서는 `error_code=10006`, `not open path`를 반환했다. 이 경로의 과거 OHLCV를 확보했다고 주장하지 않는다. 접근 제한을 우회하거나 비공개 인증을 추출하지 않았다.

원본 봉 수신 경로를 확보한 것과 기존 알림을 원본 봉 기준으로 전환한 것은 별도 단계다. 사용자 화면과의 가격 기준·RSI 기간·계산 방식 대조, 봉 마감 경계와 재연결 구간 검증이 남아 있다. 현재 코드의 `native_history_ready=true`는 이력이 쌓였다는 뜻일 뿐 자동 전환 승인이나 전략 수익성 검증이 아니다. 진입 소스는 자동 전환되지 않는다.

다른 거래소의 5분봉은 보조 검증 자료로 사용할 수 있지만 LBank 원본을 대신했다고 표시하면 안 된다. 이번 해결 경로에는 타 거래소 봉 대체나 유료 데이터 구독이 필요하지 않았다.

## 검증

```bash
python -m unittest test_lbank_native_candles.py
python -m unittest discover -p 'test_lbank*.py'
```

새 테스트 10개: 원문/압축 프레임, 진행 중 봉 제외, 연속 다섯 봉 합성, 중복 거래량, 수신 공백, 누락 봉, 시간 역전, 재시작, 잘못된 종목·가격·주기·시각, RSI 준비 조건. 실제 공개 연결에서도 초기 스냅샷과 후속 봉 수신을 검사했다. 장기 안정성과 과거 REST 봉 일치 여부까지 검증한 것은 아니다.
