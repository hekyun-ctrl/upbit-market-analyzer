## 사용자 목표와 구현 범위

목표는 거래 증거금이 아닌 **총 시드 대비 하루 순수익 7% 이상**이다. 1회 +1% 또는 하루 +7%에서 강제로 청산하지 않는다. 손절을 인정하고, 이긴 거래의 이익을 확대하는 체계다. 이 목표는 보고 지표이며 매일 달성할 수 있다고 검증된 수익률이 아니다.

예시: 10회 중 7승 3패, 패배 평균이 총 시드의 -0.5%라면 승리 평균은 `(7 + 3*0.5)/7 = 1.2142857%` 이상이어야 총 +7%가 된다. 이는 **부분익절과 잔여 청산, 비용까지 합친 거래별 순이익**이다. 승률만 70%라고 충분하지 않다. 승리 평균이 1%라면 같은 조건에서 총 +5.5%다. 이 계산은 고정 기준 시드 단순 합산이며 복리 계산이 아니다.

기존 모델은 1.5R에서 절반, 2.5R에서 나머지를 익절하면 합계 약 2R로 이익이 제한됐다(R은 초기 예상 손실). 이익을 키우는 이번 변경은 **초기 목표를 7% 역산으로 부풀리는 방식이 아니라, 유리한 움직임이 실제 이어질 때 잔여 물량의 보호선과 목표를 갱신**하는 방식이다.

- BTCUSDT 선물 단일, 격리·30배 참고, 증거금 최대 시드 15%, 초기 예상 손실 예산 시드 0.5% 유지.
- 기존 독립 전략 심사: 박스 반등/반락, 추세 재지지/재저항, 돌파. 2단계 확인과 추격 방지 유지.
- RSI는 진입 방향 정합성만 확인. 30/70 터치나 특정 RSI 구간을 새 진입 차단 조건으로 추가하지 않음.
- 기존 하루 최대 8회 및 45분 간격/반대방향 제한, 수면시간 정책 유지. 10회는 계산 예시이며 강제 할당량이 아님.
- 거래소 주문을 넣거나 계좌 잔고·실제 체결을 읽지 않는다. 본 버전은 신호 참고가 기반의 후속 알람이다.

## 추세 연장 정책 v1

새 네이티브 데이터 기반 진입 신호에만 `runner_enabled=true`가 붙는다. 배포 전 이미 보낸 신호의 전략을 소급 변경하지 않는다. 사용자가 봇에 직접 신고한 포지션이 있으면 기존 신고 포지션 알림이 우선하며, 이 참고 신호 추적은 중복 발송을 피하려고 억제된다. 신고 포지션 모듈을 이 버전에서 추세 연장으로 전환하지는 않았다.

1. 1차 목표 알림이 전달되면 잔여 50%의 참고 손절선을 진입가로 올린다. 수수료 포함 손익분기 보장은 아니다.
2. 21개 이상 연속된 최신 완료 5분봉을 사용한다. 현재 진행봉/결측/오래된 봉으로 목표를 연장하지 않는다. 진입 시점 이후에 시작한 완료봉만 보호선 갱신 근거로 사용한다.
3. EMA9/21 정렬, EMA9 기울기, 종가의 EMA9 위/아래 위치, 완료 15분 방향, RSI 변화 방향이 보유 방향과 일치해야 추세 유지로 본다. RSI 절대값은 이 조건에 쓰지 않는다.
4. 진입 후 완료봉 최고가에서 2ATR 아래(숏은 최저가에서 2ATR 위)로 보호선을 계산한다. 이미 전달한 보호선과 진입가보다 불리하게 바꾸지 않는다. 현재가에 이미 넘어선 새 보호선을 과거에 체결한 것으로 처리하지 않는다. 최소 0.25ATR 또는 진입가 0.01% 개선 때 알린다.
5. 2차 목표까지 0.5ATR 이내로 접근하고, 추세·거래량 조건이 함께 맞으면 새 목표를 기존 목표/현재가 중 더 유리한 쪽에서 2ATR 더 멀리 둔다. 박스 전략은 반대편 경계를 완료봉 기준 0.25ATR 이상 통과해야 한다.
6. 전달된 조정은 완료 5분봉당 한 번이다. 다음 새 봉에서도 조건이 맞으면 재연장 가능하다. 새로운 보호선과 목표는 텔레그램 전달 성공 후 참고 추적에 반영한다. 전송 실패 후에는 다음 시세로 재평가한다. 거래소 주문은 사용자가 직접 수정해야 한다.
7. 1차 익절 후 두 완료봉의 반대 진행과 EMA9 이탈, 또는 기존 중립 정체 정의에 해당하면 잔여 청산 알람을 보낸다. **현재 버전의 새 중립/추세 청산은 1차 익절 후 참고 신호에 적용**한다. 초기 손절·기존 조기 경고는 이전처럼 계속 작동한다.
8. 데이터 부족·추세 미확인으로 연장하지 못하면 기존 2차 목표와 현재 보호선을 유지한다. 손절 경고가 목표 연장보다 우선이다. 새 참고 신호는 최대 6시간 추적 후 청산 검토 알림으로 종료한다(이전 2시간 무알림 만료보다 연장).

2ATR/0.5ATR/EMA9·21/거래량 1배는 사전 선언한 v1 가설이다. 보편적 최적값이나 70% 승률의 증거가 아니다. 연장하면 이익을 더 얻을 수도 있고, 고정 목표에서 나왔을 때보다 이익을 돌려줄 수도 있다.

## 비용·성과 계측

- 일일 목표 기본값을 5%에서 7%로 수정. 기준자금은 환경설정값이며 실시간 계좌잔액을 자동 반영하지 않는다.
- 기존 `levels`, `warning_exit`와 새 `trend_runner`를 같은 전달 신호에서 비교. 신규 정책 비활성 신호에 새 결과를 소급 생성하지 않는다.
- 모형은 신호가 진입 체결, 목표 접촉 체결을 가정하며 텔레그램 후속 전달 여부와 독립적으로 즉시 조정한다. 실제 알림 조정과 모형 조정에는 전달 지연 차이가 있을 수 있다. 실제 계좌 손익으로 표시하지 않는다.
- 관측 사이 150초 초과 공백은 수익/손실 판정에서 제외(censored)하고 별도 수량을 표시한다. 표본 사이 순간 손절/목표 접촉은 놓칠 수 있다. 신호 간 중복 노출도 실제 단일 계좌 포트폴리오로 정규화한 것이 아니다.
- 기본 taker 편도 0.06%, 청산 불리한 슬리피지 0.02%, 명목금액의 펀딩 예비비 0.01%. 개인 등급/지정가 체결/실제 펀딩 시각·금액은 미확인이다. 특히 연장 보유 시 예비비가 실제 펀딩을 충분히 덮는다는 보장은 없다.
- 최종 순이익 >0인 완료 거래만 승리. 평균 승/패, 거래당 순기대값, Profit Factor, 완료 모형 손익의 낙폭, Wilson 승률 구간을 계산. Wilson 구간은 독립성 가정의 기술 통계이며 상관된 매매의 미래 승률 인증이 아니다.
- 신호별 새/기존 모형이 **둘 다 완료된 경우**만 쌍별 순익 차이를 산출한다. 미완료가 많은 때의 편향은 여전히 있으므로 건수를 함께 표시한다. 각 정책 결과를 합산하지 않는다.
- 매일 22:50 KST 기존 보고에 추가. 해당 날짜 생성 신호의 중간집계이며, 전날 시작한 포지션·미완료 거래를 포함한 계좌의 하루 순수익이 아니다. 7% 목표 달성 확정을 자동 선언하지 않는다.
- `runner_adjustments` 테이블은 모형 조정 근거, `RUNNER_FOLLOWUP_SENT` 로그는 실제 알림 전달된 보호선·목표의 기록이다.

## 실제 데이터와 검증

현재 작업에서 확보한 네이티브 5분봉 로그 **53개, 4시간 25분**, 연속성 공백 0개, 가격 고가 81,733 / 저가 81,480.7. `research/native-5m-audit-20261017.json`과 `research/audit_native_5m.py`로 재현한다. 원본 1분봉 집계 및 스트림 진행으로 마감을 추론했다. 거래소 차트/REST 완결봉과 독립적인 대조는 아직 없다.

이는 자료 연결·형식 검증이며 수익 백테스트가 아니다. 1분 전체 이력 없이 5분봉을 가짜 1분봉으로 쪼개지 않았다. 53개 봉으로 일일 수익 분포·월간 낙폭·70% 승률·7% 달성을 입증할 수 없다. 이전 가격표본 재생의 손실 결과를 이번 새 정책의 성과로 바꾸어 보고하지 않는다.

검증 명령:

```
python -m unittest discover -p 'test_lbank*.py'
python research/audit_native_5m.py
```

로컬 220개 통과(기존 194개 + 새 26개). 롱/숏 대칭, ATR, 거래량·상위봉 반대, 박스 경계, 데이터 공백, 실패 전달, 재시작, 보호선 단조성, 반복 목표 연장, 비용·부분익절·쌍별 비교를 포함한다. 이는 구현 검증이지 수익 검증이 아니다.

앞으로 축적되는 기록을 검토할 때는 서로 다른 장세와 날짜를 포함한 최소 수주 구간, 비용 변화, 미완료/공백·중복 노출, 독립 보유 구간, 모형 대비 실제 수동 체결 차이를 확인해야 한다. 이 문서가 추가 AI 연구나 무인 재배포를 예약한 것은 아니다. 서버의 이미 구현된 수집·알림·집계만 지속된다.

## 운영 및 롤백

GitHub `feature/lbank-futures-monitor` 변경에 연동된 기존 Railway LBank 서비스만 배포한다. 기존 `/data` DB와 신고 포지션은 보존한다. `LBANK_TREND_RUNNER_ENABLED=false`면 신규 신호는 기존 목표 방식으로 돌아간다. 이미 연장 알림을 보낸 신호는 전달한 보호선·목표를 지키기 위해 해당 신호의 추적을 유지한다. 과거 코드로 전체 롤백하면 수익 방향으로 옮긴 보호선 복원 호환성이 없으므로 **새 코드에서 신규 runner만 끄는 방식**을 우선 사용한다.
