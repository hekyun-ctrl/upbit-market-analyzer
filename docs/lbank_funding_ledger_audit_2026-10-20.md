# Funding Harvester: 공개 BTC 기본 장부의 현금·비용·빈도 검산

2026-10-20. **원전의 작은 OOS 양수는 현금 장부에서 재현됐다. 그러나 PF·기대수익 불확실성·빈도·두 배 비용 및 수동 보호 계약이 채택 기준을 충족하지 않아 운영 교체하지 않는다.** 다른 거래소의 공개 모형 장부 계산이며 실제 LBank 수익이나 새 시장 백테스트가 아니다. 한 해 손실로 모든 펀딩/역추세 기법을 무효라 하는 것도 아니다.

## 수수료·슬립·펀딩의 별도 대조

기본 현금은 체결가×수량의 실제 부호, 양쪽 명목금액 수수료, 원전 펀딩 손익으로 다시 계산했다. 체결가에는 이미 불리한 슬립이 들어 있다. 이를 다시 비용으로 빼면 이중 차감이다.

- 원문 `extract_trade_returns`는 슬립을 다시 빼고 펀딩을 빠뜨렸다. 그 함수로 계산한 OOS 거래 손익 합계는−19.238010 USD지만 현금 기준은+11.079637 USD다. 차이−30.317647은 추가 슬립−29.007072와 펀딩 누락−1.310575의 합계로 설명된다. **이 오류는 해당 통계값을 낮추는 방향**이며, 원문의 계정 말단 +11.079637 자체를 가짜 양수라 하지 않는다.
- IS 함수 합계−1,206.679887과 현금−1,085.796970의 차이−120.882917도 추가 슬립·펀딩 누락과 일치했다.
- 비용 두 배는 **원래 수량·시간·진입/종료 선택을 고정**했다. 일반 체결가에서 원시 시가를 역산하고 슬립2bp·수수료12bp로 다시 계산했다. 펀딩 지급만 두 배, 수취는 그대로 두어 유리한 수취까지 배로 늘리지 않았다. 실제 거래소 비용·호가·펀딩 mark를 검증한 것이 아니므로 native 전체비용 통과값으로 사용하지 않는다.

원문은 다음 시가 체결을 전 시간봉의 포지션·비용·equity에 먼저 기록한다. 원문 시간 색인을 그대로 재생하면 equity 최대 오차는 IS2.18e−11/OOS3.64e−12 USD였다. 같은 체결을 실제 기록된 시각으로 옮긴 경로와 최대 약3.60 USD 차이가 났다. 종료 현금은 같았으며, 이것을292개 진입 신호의 미래 누출이나 전체 수익 조작으로 일반화하지 않았다. 이 검사에서 미래 의존성이 확인된 대상은 **평가 경로의 시간 배치**다. 펀딩 금액도 정산 시간의 실제 거래소 mark가 아니라 원문 시간봉 종가 모형이므로, 실제 지급/수취로 확정하지 않는다.

## 자료 정합성과 원전 버전 한계

파일명만 보고 `data/raw/btcusdt_1h.csv`를 사용하지 않았다. 그 파일은2024-05~2025-05만 있어 OOS를 덮지 못한다. 원문 registry와 기본 경로를 대조해 **`btcusdt_1h_2yr.csv` 18,985행**(2024-03~2026-05)을 연결했다. `_full`20425행은2024년1월부터의 다른 실행 경로다.

세 원본 CSV와 clean Parquet 모두 시간 중복0·시간 간격 공백0·비유한 가격/거래량0·음수/0가격0·OHLC범위 오류0이고, 공통 원본/clean OHLC 차이는0이었다. 선택 입력의 펀딩은2,374행·중복0이다. loader에 공백 forward-fill 코드가 있지만 **이 선택 입력에서 공백을 발견한 것은 아니다.** 거래별 필요한 시간도 모두 있었고, 소스의 임의 자료끝 청산이 이번 결과를 만들지 않았다.

25입력 파일의 Git blob SHA·전체 SHA256·바이트 수를 계산 전에 확인하고 [보고서](../research/continuation/results/funding_ledger_20261020/report.json)에 저장했다. 원본은 위 고정 저자 Git에 그대로 보존돼 있다. 이는 공개 파일과의 일치이며 Bybit 거래소에서 독립 재수집한 진위 인증은 아니다. 다른 거래소/자산을 BTCUSDT/LBank로 바꾸지 않았다.

원문의 registry `data_hash`는 MD5이며 전체 데이터가 아니라 첫100개 시각·종가와 총길이만 해시한다. 101번째 값만 바꾸면 해시가 그대로인 대조를 통과했다. registry의 실행 커밋은7cc804f이고 `git_dirty=true`이므로 정확한 당시 미커밋 규칙 복원은 확정할 수 없다. 우리 기록은 배포된776003e의 원문·전체 입력 SHA와 저장 장부 산술을 구분한다. 이번에 원문 규칙을 다시 실행해 같은 신호 장부를 생성했다고 주장하지 않는다.

## 판정·후속

원전 기본 버전은 교체 미승인이다. 일부 양수가 존재한다는 사실과, 현재 수동 알람 기준을 통과한다는 주장은 다르다. 이미 관측한2024~2026자료·선택된 원문 결과를 새 순방향으로 부르지 않으며, 종목 선택·설정 탐색·손실 상한 완화로 통과시키지 않는다. TP1·즉시 역행·긴급 후속·native 호가/체결·30일/100종료 근거는 없다. 전향 수집은 시작하지 않았다.

후속 원전 검색에서는 기존 Pavdot/기술규칙3669개 원전을 중복 목록에서 확인해 새 백테스트로 세지 않았다. 새 regime 원전은 현물·최소42시간 보유·원본/장부 미공개라 현재 빈도 계약에 맞지 않았다. 새 MACD 원전08e5f1a의 Git 트리는 확보했지만 README promisor 다운로드가 CONNECT403으로 중단됐다. 이 접근을 재시도하거나 권한 제한을 우회하지 않았다. arXiv2201.04699v4 직접 열기도 웹 도구 DisabledError로 실패했으며 원문 전체를 읽었다고 하지 않는다.

다음 유한 단계는 공개 양수 주장이 있는 별도 [원저자/기관 논문](https://discovery.ucl.ac.uk/id/eprint/10147117/)의 정확한 규칙·입력·실행/코드/종료장부 공개 여부와 수동 BTCUSDT 적합성을 확인하는 것이다. 제목은 *The Recurrent Reinforcement Learning Crypto Agent*, DOI10.1109/ACCESS.2022.3166599다. 기관의 서지/초록만 확인한 조사 대상이며 저자 순수익350% 주장을 우리 성과로 채택하지 않는다. 원문/공개 코드와 실제 입력이 없으면 훈련·임의 복제·사적 자료/연락처 접근 없이 장애를 기록하고 다른 공개 원전으로 이동한다. 아직 논문 규칙 버전이나 원자료 SHA를 고정한 합격 후보가 아니다. 특정 소스 접근 오류가 전체 연구 불가능으로 확인된 것은 아니다. 구체적 순서와 장애는 `state.json`에 남겼고, 이미 제외한 펀딩 기본 버전을 재계산·튜닝하지 않는다.
