# 진입 확인의 분석 주기 대기 제거 — 2026-10-20 KST

상태: 확인 지연 수정. **전략의 양의 기대수익·목표 도달률 개선을 입증한 변경은 아니다.** 기존 대안 연구에서 교체 가능한 우위를 아직 확보하지 못했다는 판정은 그대로다.

## 확인한 경로

기존 `run()`은 위험·가격을 기본 15초마다 확인하지만, 대기 중 후보의 `confirm_watch()` 호출은 기본 60초짜리 표본 분석 블록 안에 있었다. 함수 자체는 30초부터 기존 심사를 허용하는데도, 다음 분석 주기까지 기다릴 수 있었다. 신호 후보 발견 이후의 불필요한 스케줄 지연이다. 지표 계산에 필요한 완료 봉을 생략하는 문제가 아니다.

수정 후 후보 발견과 원래 가격 표본 저장은 60초 주기를 유지한다. 대기 중 후보는 최소 30초가 지난 뒤 각 위험 점검 루프에서 최신 관측가·원본 봉·기록 상태로 확인한다. 최소 30초, 후보 유효시간 240초, 가격 추격 한도 0.10%, 원래 구조·방향·손익비·위험·발신 제한과 목표 전 보호 정책은 유지한다. 위험 통지 처리를 확인보다 먼저 실행한다.

## 운영상 범위와 한계

실제 확인 시각은 네트워크와 루프 실행 시간의 영향을 받는다. 실시간 30초 발신 보장이 아닌, 30초 이후 첫 이용 가능한 점검에서 확인하는 변경이다. 그때 시장·심사 조건이 맞지 않으면 발신하지 않는다. 신호 횟수·진입 가격·손익에 미치는 영향은 실제 후속 관측이 필요하다.

빠른 확인 재시도로 확인 거절 카운터가 더 자주 늘 수 있으므로 이전 버전의 확인 시도 횟수를 그대로 비교해 정확도 변화로 해석하면 안 된다. 실제 발신과 종료 거래를 기준으로 성과를 구분해야 한다.

배포는 프로세스를 재시작한다. 재연결이 분 경계를 지나 원본 봉에 공백이 생기면 기존 규칙대로 연속 이력이 다시 확보될 때까지 진입을 차단한다. 공백을 보간하거나 원본 봉 품질을 바꾸지 않는다. 배포 성공과 진입 준비 상태는 따로 확인해야 한다.
