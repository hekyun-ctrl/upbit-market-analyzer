## 시각·복구 정책

- 입력은 실제 도착 순서대로 처리한다. 봉 내부 손절/부분익절 처리 이후 b.end 시장 구간의 KST 경계를 확정한다. 이벤트 통지/행동 시각은 원래 now(수신 처리 시각)로 유지한다.
- 전일 종료/다음 날 시작 NAV는 같은 값. `market_cutoff`와 `received_at`을 함께 저장한다. 180초 지연 도착에서도 이 원칙을 시험했다. 최종 관찰일은 임시 집계로 `partial_observation_day=true`; 가짜 자정을 생성하지 않는다.
- 이미 확정된 날보다 오래된 입력은 재소급하지 않는다. 역순/미해결 날짜 경계는 실패 또는 DAY_ACCOUNTING_UNRESOLVED로 보존하며 순성과 합격을 허용하지 않는다. 이 수정은 tick기반 실시간 경로 완성이라는 뜻이 아니다.
- daily_halted는 한도 최초 도달 후 고정. 회복/재시작에도 유지하고 다음 KST일에만 reset. 5% review는 reset하지 않는다. 보유 중 손절은 계속 동작한다.
- 입력 상품·완료·geometry 검증은 중복 확인 **전에** 수행. 경제적 내용 동일 재수신은 상태/장부/정정 변경 없이 최초 수신 유지. 실제 내용 정정은 별도 기록/재생 버전 필요. 기존 DB의 v1키도 조회해 이전 저장소 중복을 유지한다.
- 1m/5m 장애 원인을 별도 저장한다. 최신5m 일치만으로 전체 건강 상태를 지우지 않는다. 이미 불확실 구간을 지난 포지션의 DATA_CENSORED는 복구 후에도 남는다.
- 기존 snapshot 호환: 새 latch/원인 상태는 기본값으로 시작. 기존 snapshot의 펀딩이 0이 아닌데 잔여 배분 필드가 없으면 LEGACY_FUNDING_ALLOCATION_UNKNOWN으로 표시한다. 과거 배분을 임의 추정해 검증 순손익을 생성하지 않는다.

## 시험

```bash
python -m unittest discover -s tests/zerobase -v
```

기존31개+회귀7개=38개 통과. 반복 시나리오는 각각의 함수 안에서 확인하며 거래 표본이 아니다. 기존 시험 중 ‘항상 정확25%’였던 수량 기대값1곳만 새 step 내림 규칙으로 바꿨다. 손절/거래/위험 차단 기대를 약하게 바꾸지 않았다.

추가 검증 범위:
- 재수신→재시작→재수신/상품 혼용 거부/실제 정정 보존.
- 필수60분 안에 누락이 남는 경우→차단, 새 연속 이력 충족→해제, 과거 불일치 남음→다시 차단, 보유 censor 유지.
- 롱·숏1~9개 수량단위, 4로 나누어떨어지지 않는 수량, 최소주문에 미달하는 부분량, 합계 보존/실제비율.
- 롱·숏, 0/2/5bp, 수수료, 펀딩 지급/수령, 부분 전후 정산에서 잔여 본전 net≥0.
- 일 손실→회복→snapshot 복원→그날 진입차단→다음날 자격복구, DD review 유지.
- 자정 전 stop/부분청산/열린 포지션/180초 수신지연/마지막관찰일 NAV.
