# LBank 선물 알람 제로베이스 구현 설계서

**버전:** ZB-1.0 · **작성일:** 2026-10-21 KST · **구현 대상:** Sol 6.1

**문서 상태:** 구현 가능한 연구 명세. 전략 수익성은 미검증이며, 아래 수치는 사전 고정할 초기 가설이다. 이 문서 작성으로 코드 변경·배포·알림 재개·자동 주문이 실행되지는 않는다.

## 0. 인수인계와 작업 범위

이 파일만으로 새 설계의 구현을 시작할 수 있게 작성했다. 다른 대화의 전체 내용을 다시 수집하지 않는다. 실제 구현에 착수할 때에는 사용자가 다른 방에서 내린 일시중지·재개 지시 중 최신 지시를 먼저 확인한다. 이 문서 자체를 운영 재개 승인으로 해석하지 않는다.

최초 범위는 **LBank의 BTC/USDT 선형 USDT 결제 무기한 선물 1종목, 롱·숏 알람과 모의 장부**다. Upbit 현물과 다른 거래소의 선물은 별도 상품이다. 자동 주문, 자금 이동, 개인 계좌 접근은 범위에 포함하지 않는다.

### 사용자가 요구한 결과

- 기존 알람의 진입 조건·점수 체계가 옳다고 전제하지 않고 매매 판단을 새로 설계한다.
- 알람에는 진입 가능 가격, 유효시간, 손절, 무효화, 수익 관리, 비용과 위험을 명확히 표시한다.
- 방향과 구조가 유지되면 수익을 더 가져간다. 시드 수익률 1% 같은 획일적 전량 익절을 사용하지 않는다.
- RSI·다이버전스·BTC 도미넌스·USDT 정보를 검토하되, 추가할 때마다 공통 필수 조건을 늘려 신호가 사라지게 만들지 않는다.
- 1~2일 안에 설계 구현과 확보 자료에 대한 재현 결과를 먼저 제시한다. 부족한 데이터나 불합격 결과도 그때 보고한다.
- Astra는 설계와 중요한 결과 검토에 집중한다. 수집·계산·모의 추적은 일반 프로그램, 구현·반복 수정은 Sol 6.1이 맡는다.

### 명확히 구분할 사항

일일 순수익 7%는 사용자의 희망 목표이며, 진입 횟수·레버리지·위험을 강제로 올리는 제어 목표가 아니다. 새 알람의 정확도·수익성·7% 달성 가능성은 결과로 측정한다. 지표를 많이 넣거나 유명 거래자의 이름을 붙이는 것으로 성능을 인정하지 않는다.

기존 수집·저장·발송 기능은 상품·시각·복구 정확성을 확인한 뒤 재사용할 수 있다. 기존 전략은 동일 자료에서 비교할 대조군으로만 보존한다. 이 작성 시점에는 최신 운영 코드와 계좌 잔액을 다시 조회하지 않았으므로, 이전 대화의 배포 상태·시드·레버리지를 현재 사실로 복사하지 않는다.

### 최우선 완료 요구: 기존보다 높은 완성도

사용자는 새 설계가 기존 설계보다 완성도가 높아야 한다고 명시했다. 이를 다음 네 항목으로 판정한다.

1. **판단 일관성:** 진입 근거·주의·무효화·손절·수익 관리가 하나의 고정된 상태 모델로 연결되어 모순되지 않는다.
2. **경제성:** 같은 원본 자료, 비용, 체결 지연, 시드 위험으로 비교했을 때 비용 후 성과가 개선되는지 확인한다.
3. **가용성:** 신호가 없어진 이유, 놓친 후보, 중복 제거, 사용자 대응 가능 시간까지 측정한다.
4. **운영 신뢰성:** 데이터 공백·재시작·전송 실패·봉 안의 순서 불명확 상황에서도 신호와 성적을 잘못 기록하지 않는다.

문서가 자세하거나 테스트 개수가 많다는 이유로 ‘기존보다 우수’ 판정을 내리지 않는다. 경제성 또는 가용성의 비교 근거가 없으면 설계·기능 완료와 성능 미입증을 함께 표시한다. 교체 판정은 10.6절을 따른다.

## 1. 완료 수준과 개발 순서

| 단계 | 산출물 | 완료 판정 |
|---|---|---|
| P0 자료 확인 | 원본 데이터 목록, 상품 식별, 결손·비용 자료 보고 | 사용 가능한 범위와 미확인 항목이 숫자로 표시됨 |
| P1 규칙 구현 | 아래 세 전략, 상태 관리, 비용·위험 계산기 | 고정 입력에서 결과 재현, 미래 정보 사용 없음 |
| P2 과거 재생 | 전략별·통합 성적표, 실패 사례, 기존 전략 비교 | 자료 부족·불합격도 포함해 결과 공개 |
| P3 모의 연결 | 새 규칙의 수신·판정·저장·발송 연동 | 재시작·중복·전송 실패 복구 통과 |
| P4 채택 검토 | 실제 시간에 새로 모은 모의 결과 | 사전 고정 기준에 따라 채택·보류·폐기 |

**1~2일 목표는 P0~P2와 가능 범위의 P3**다. 아직 존재하지 않는 미래 30일의 결과를 포함하지 않는다. 자료가 부족하면 P0에서 명확히 보고하고, 자료를 기다리는 동안 P1의 재현 가능한 모듈을 완성한다. 구현 완료와 전략 검증 합격은 별개다.

기존 대화의 ‘최소 30일·종료 100건’은 기존 검증 계획의 기준이다. 이를 문헌 100개를 읽는 기간으로 설명하지 않는다. 새 설계는 아래 기준으로 별도 버전 관리하며, 기존 기준의 충족 여부와 새 기준의 충족 여부를 섞지 않는다.

## 2. 데이터 계약과 공급원

### 2.1 필수 데이터

1. 동일 LBank 선물 상품의 원본 완료 1분봉 및 5분봉 OHLCV.
2. 동일 상품의 최신 체결가, 최우선 매수·매도 호가와 수신 시각. 호가가 없으면 관찰·계산은 가능하지만 실행 가능한 진입 알림은 보류한다.
3. 상품 코드, 선형/역선형, 결제 통화, 수량 단위·계약 승수, 가격·수량 간격, 최소 주문 조건.
4. 수수료 적용표와 출처·확인일. 수수료 할인이나 메이커 체결을 근거 없이 가정하지 않는다.
5. 실제 펀딩 정산 시각·확정 요율·정산 기준 가격. 펀딩 간격을 고정 8시간으로 가정하지 않는다.[S2]
6. 신호 발생·발송·수신 확인·모의 체결 시각. 사용자 실제 체결과는 구분한다.

15분봉은 같은 상품의 연속된 완료 5분봉 3개로 만든다. 시각 경계는 UTC 기준이며 표시는 KST로 한다. 1시간 정보는 v1의 선택적 참고 정보다. 필수 데이터가 없는 것을 지표 값 0으로 대체하지 않는다.

### 2.2 공급원 확인 절차

- 기존 구현에 선물 원본 봉 어댑터가 있다면 해당 응답을 먼저 검증한다. 이번 문서는 과거 대화에서 발견했다는 연결이 현재도 정상이라고 가정하지 않는다.
- 공식 문서에는 현물과 계약 API의 별도 경로가 있다.[S3] 현물의 K선 API를 선물의 원본 봉으로 사용하지 않는다.
- 기존 선물 어댑터와 공식 계약 자료에서 상품 종류·가격 단위·봉 시각을 대조한다. 공개 문서에 없는 엔드포인트를 추측해 명세에 확정하지 않는다.
- TradingView의 LBank BTCUSDT.P는 차트 대조 대상이다.[S4] 차트 제공 사실을 무제한 과거 데이터 API 제공의 근거로 사용하지 않는다.
- 연결 확인 결과에는 요청 경로, 상품 식별, 응답 필드, 가장 이른·최근 봉, 페이지 제한, 호출 제한과 오류 예를 남긴다. 자격 증명은 기록하지 않는다.
- 다른 거래소·현물·가격 표본을 원본 선물 봉의 빈칸에 넣지 않는다. 대체 자료 실험은 별도 데이터셋·성적표에만 둔다.

### 2.3 시간과 완전성

각 레코드는 다음을 갖는다.

~~~text
exchange, market_type, symbol, settlement_asset, price_basis,
timeframe, open_time_utc, close_time_utc,
open, high, low, close, volume, volume_unit,
is_closed, source, received_at_utc, revision, content_hash
~~~

- 봉 구간은 [open_time, close_time)이다. 공급자 시각이 초/밀리초 또는 시작/종료 중 무엇인지 어댑터에서 정규화한다.
- 판단에는 실제로 수신된 완료봉만 쓴다. 과거 재생에서는 해당 봉의 종료 이후에만 접근한다.
- 동일 상품·봉 간격·시작 시각을 기본키로 저장한다. 중복 수신은 거래 표본을 늘리지 않는다.
- OHLC 순서 관계, 음수 거래량, 중복·역순·누락 시각, 거래량 단위를 확인한다.
- 1분봉 집계와 원본 5분봉의 가격 허용 오차는 1 tick으로 시작한다. 거래량은 동일 단위일 때만 비교하며 오차 기준과 원인을 보고한다. 불일치를 평균으로 덮지 않는다.
- 실시간 최신 호가의 최대 나이는 5초, 완료 1분봉·5분봉의 예상 수신 지연 허용은 15초를 초기 운영 기준으로 둔다. 미달 시 DATA_DEGRADED로 진입만 보류한다.
- 봉 신선도는 ‘마지막 봉이 닫힌 뒤 15초’가 아니라 ‘새로 닫혀야 할 봉의 도착 기한’으로 판단한다. 예를 들어 12:05 종료 5분봉이 12:05:15까지 없으면 지연이다. 그 봉이 정상 도착했다면 12:09에 4분 오래됐다는 이유로 지연 처리하지 않는다.
- 재연결 후에는 누락 구간을 보충하고 지표를 재계산한다. 새로 수신된 과거 신호를 현재 진입 알람으로 보내지 않는다.
- 재시작 때 저장된 봉과 상태를 복원한다. 매번 처음부터 봉을 쌓는 구조를 피한다.

자료 품질 기준은 신뢰 가능한 입력의 조건이다. 공급자 실제 지연과 다른 임계값이 필요하면 자료 보고서에 근거를 쓰고 버전을 바꾼다. 알람 수를 늘리기 위해 불완전한 봉을 완료봉으로 처리하지 않는다.

## 3. 계산 정의와 시장 상태

v1의 모든 진입 전략은 **완료 5분봉**에서 판정한다. 1분봉은 체결 재생·손절 관찰·전송 지연 검증에 사용한다. 공통으로 완료봉 두 개를 더 기다리는 조건은 없다.

### 3.1 지표

- EMA(n): 최초 n개 종가의 단순평균으로 시작하고 이후 alpha=2/(n+1)로 갱신한다.
- TR=max(H−L, |H−이전 C|, |L−이전 C|), ATR(14): 최초 14개 TR 평균 후 Wilder 방식으로 갱신한다.
- RSI(14): Wilder 평균 상승·하락폭. 둘 다 0이면 50, 하락폭만 0이면 100, 상승폭만 0이면 0.
- ER(12)=|C[t]−C[t−12]| / sum(|C[i]−C[i−1]|, i=t−11..t). 분모 0이면 0.
- pivot high/low: 좌우 2개씩보다 엄격하게 높은 고점/낮은 저점. 동률은 pivot으로 인정하지 않는다. 봉 t의 pivot은 t+2 종료 때만 알려진다. pivot_time과 known_at을 따로 저장한다.
- 진입에 쓰는 초기 ATR은 **신호 봉 직전까지 계산한 5분 ATR14**, A라고 부른다. 신호 봉의 큰 움직임으로 완충 폭을 즉석 확대하지 않는다.

초기 계산 전 연속된 완료 15분봉 150개, 5분봉 150개, 1분봉 60개를 확보한다. 단절 이전 지표를 아무 표시 없이 이어 붙이지 않는다. 선택적 1시간·도미넌스 자료 부족은 이 필수 워밍업을 늘리지 않는다.

### 3.2 15분봉 상태

최신 완료 15분봉의 ATR을 B라고 한다. B=0 또는 필수 자료 부족이면 UNKNOWN이다.

~~~text
z = (EMA20 - EMA50) / B
slope = (EMA20[t] - EMA20[t-3]) / B
우선순위:
1. z >= 0.10 and slope >= 0.05       -> TREND_UP
2. z <= -0.10 and slope <= -0.05     -> TREND_DOWN
3. abs(z) <= 0.25 and ER12 <= 0.25   -> RANGE
4. 그 외                           -> TRANSITION
~~~

이는 검증할 초기 분류기이며 시장의 참 상태나 승률이 아니다. RANGE와 TRANSITION도 전용 전략에서 평가한다. UNKNOWN은 반대 방향의 증거가 아니다.

## 4. 세 가지 독립 진입 전략

각 전략은 독립적으로 후보를 만든다. 다른 전략의 조건까지 모두 만족시키는 AND 결합은 하지 않는다. 아래는 롱 기준이며 숏은 가격 부등호·고저·봉 위치를 대칭 변환한다. 봉 내 종가 위치 CLV=(C−L)/(H−L), H=L이면 0.5로 정한다.

### A. 추세 되돌림 — TREND_PULLBACK

필요 시장 상태는 TREND_UP이다. 신호 5분봉을 t라고 할 때:

1. t 직전 3개 봉 중 하나 이상에서 종가가 해당 시점 EMA20(5m)+0.30×해당 시점 ATR14(5m)보다 높았다.
2. L[t] <= EMA20(5m)[t−1]+0.15A, C[t] > EMA20(5m)[t−1].
3. C[t] > C[t−1], CLV[t] >= 0.60.
4. C[t]−EMA20(5m)[t−1] <= 0.80A. 지나치게 멀어진 가격은 새 되돌림을 기다린다.

구조 기준값 F=min(L[t−2],L[t−1],L[t]). 초기 손절 S=F−0.15A. 구조 무효화 기준 I=F−0.05A. 이 세 값은 신호 생성 때 고정한다.

### B. 돌파 후 재지지 — BREAKOUT_RETEST

시장 상태는 TREND_UP 또는 TRANSITION이다.

1. 돌파 봉 b 직전 24개 5분봉의 최고가 U, 최저가 D를 계산한다. 돌파 봉 자체를 범위에 포함하지 않는다.
2. C[b] > U+0.10A_b, CLV[b] >= 0.70이면 감시 후보를 만든다. U, D, A_b를 고정한다.
3. 이후 **최대 3개** 완료 5분봉 중 첫 번째로 L[t] <= U+0.15A_b, L[t] >= U−0.35A_b, C[t] > U, CLV[t] >= 0.60을 만족하면 진입 후보를 만든다.
4. 재지지 전에 완료봉 종가가 U−0.35A_b 아래이면 감시 종료. 3개 봉 안에 조건이 없으면 만료한다.

F=U, S=min(U−0.35A_b, 재지지 봉 L[t]−0.10A_b), I=U−0.20A_b. 손절과 무효화가 진입 가격 반대쪽에 올바르게 놓였는지 공통 계산기로 확인한다.

이 전략은 실제 재지지를 관찰한다. 모든 전략에 추가 대기 시간을 붙이는 것과 구분한다. 돌파 봉 가격을 이미 지나간 체결가로 기록하지 않는다.

### C. 박스 이탈 실패 후 복귀 — FAILED_BREAK_RECLAIM

시장 상태는 RANGE 또는 TRANSITION이다. t 직전 24개 5분봉의 최고가 U, 최저가 D를 고정한다.

1. L[t] < D−0.10A로 기존 하단을 이탈했다.
2. C[t] > D+0.05A로 범위 안에 복귀했다.
3. CLV[t] >= 0.65.

F=D, S=L[t]−0.15A, I=D−0.05A. 이 전략의 첫 구조 목표는 (U+D)/2다. 강한 하락 상태에서 단지 RSI가 낮다는 이유로 롱을 만들지 않는다. 숏은 상단 이탈 후 복귀를 대칭 적용한다.

### 4.1 후보 공통 처리

- 종목·방향별로 신호 생성 가격 C[t]부터 유효시간 120초를 부여한다.
- 최초 손절까지의 가격 거리 D0=|C[t]−S|를 기준으로 허용 진입 범위를 C[t]±0.15D0로 고정한다. 불리한 쪽으로 범위를 넓히지 않는다.
- 실제 진입 가능 가격은 최신 호가와 수량에 따른 체결 추정값으로 다시 계산한다. 허용 범위 밖, 만료, 손절 선행 도달, 구조 무효화 선행 발생이면 EXPIRED/CANCELLED로 끝낸다.
- 규칙에 맞는 후보라도 비용·가격 구조·자료 신뢰·위험 한도는 확인한다. RSI, 거래량, 도미넌스 결측만으로 탈락시키지 않는다.
- 세 전략을 같은 종목에서 동시에 포지션 세 개로 쌓지 않는다. 통합 모의 장부에는 활성 포지션 최대 1개다.
- 같은 방향 후보가 겹치면 비용 후 목표 손익비가 높은 후보, 같으면 감시 생성이 빠른 후보, 그래도 같으면 A→B→C 순서로 선택한다. 다른 후보는 SUPPRESSED_OVERLAP으로 기록한다.
- 같은 판정 시각에 롱·숏이 충돌하면 둘 다 CONFLICT로 기록한다. 임의로 유리한 사후 결과를 선택하지 않는다.
- 새 봉·새 패턴 없는 반복 메시지는 새 거래가 아니다. 손절 후에는 종료 신호보다 늦게 형성된 새 후보 기준과 별도 확인 봉이 필요하다.

## 5. RSI·다이버전스·도미넌스·기존 연구의 위치

### 5.1 RSI와 다이버전스

v1에서는 설명과 분석용 feature로 기록한다. RSI 70 이상을 일괄 숏, 30 이하를 일괄 롱으로 바꾸지 않는다. 진입 차단이나 보유 중 조기 청산을 추가하지 않는다.

일반 상승 다이버전스는 최신 두 개의 **확정된** 5분 pivot low 사이에서 두 번째 가격 저점이 낮고, 그 저점 시점 RSI는 3포인트 이상 높은 경우다. pivot 간 거리는 3~30개 봉, 최신 pivot 확정 후 유효기간은 6개 5분봉이다. 하락 다이버전스는 대칭이다. 확정되기 전의 pivot을 과거 신호에 소급 적용하지 않는다. 숨은 다이버전스는 v1에서 제외한다.

이 정보가 유용한지는 핵심 규칙만 사용한 결과와 추가 사용한 결과를 비교해 판단한다. 성과 근거가 생기기 전에는 원천 후보를 줄이는 필수 조건으로 승격하지 않는다.

### 5.2 BTC 도미넌스와 USDT

다음 세 항목은 서로 다른 값이다.

- BTC.D: BTC 시가총액 / 동일 공급자의 전체 암호자산 시가총액.
- USDT.D: USDT 시가총액 / 같은 기준의 전체 시가총액.
- USDT/USD: 1달러 대비 가격 이탈 정도.

동일 공급자·동일 기준 시각의 원자료를 저장한다. 원자료가 1시간·일 단위이면 5분 변화처럼 보간하지 않는다. 1시간 변화는 1시간 간격 관측치가 있을 때만 계산하고, 조회된 시각보다 앞선 판단에 쓰지 않는다. 공급 주기 2배보다 오래된 자료는 UNKNOWN으로 표시한다.

v1에서는 CONTEXT_SUPPORT/CONTEXT_CONFLICT/UNKNOWN 태그와 원값만 기록한다. 변화 방향을 자금의 실제 유입·유출이나 BTC 상승·하락 확정으로 해석하지 않는다. 태그는 후보 선택·위험 증액·손절 변경에 관여하지 않는다. 이는 데이터 연결과 검증 기반을 먼저 적용하는 범위다.

### 5.3 앞서 검토한 거래자 기법

나씨·매억남·김직선·워뇨띠 관련 자료는 출처가 확인된 관찰만 가설 등록부에 남긴다. ‘지지·저항, 추세 동행, 실패 돌파, 손절, 수익 확대’처럼 코드로 표현 가능한 규칙을 본 설계와 비교한다. 본 문서의 세 전략을 특정 인물의 실제 전략 복제라고 표시하지 않는다. 해당 자료를 처음부터 모두 다시 수집하는 일을 이번 1차 구현의 선행 조건으로 두지 않는다.

## 6. 비용·목표·시드 위험 계산

### 6.1 가격과 수량

수량 q는 BTC 수량으로 정규화한다. 거래소 주문 수량이 계약 수이면 계약 승수로 변환한다. 손익식에 계약 수와 BTC 수량을 혼용하지 않는다.

P_e는 진입 체결 추정 가격, P_x는 청산 체결 추정 가격이다. 호가 차이와 슬리피지는 이 가격들에 반영한다. 동일 슬리피지를 별도 비용으로 두 번 빼지 않는다. 방향 d는 롱 +1, 숏 −1이다.

~~~text
gross_pnl = d × q × (P_x - P_e)
net_pnl = gross_pnl - entry_fee - exit_fee - funding_paid
entry_fee = q × P_e × fee_entry
exit_fee  = q × P_x × fee_exit
funding_paid = 각 실제 정산 시각의 부호 있는 지급액 합계
~~~

부분 청산은 각각 계산하고, 펀딩은 정산 시각에 남아 있던 수량에만 적용한다. 수령 펀딩은 funding_paid가 음수다. 미래의 미확정 펀딩은 예상 비용으로 표시하고 검증된 순손익과 구분한다.

수수료·펀딩이 미확인이면 UNKNOWN을 저장한다. 값 0으로 채워 순수익을 발표하지 않는다. 가격 성과, 가정 비용 후 성과, 실제 요율 확인 후 성과를 별도 열로 둔다.

최초 계획의 예상 펀딩은 향후 6시간 안에 알려진 정산 시각만 대상으로 한다. 지급 요율 가정은 max(현재 표시 요율의 절댓값, 확보된 최근 30일 확정 요율의 최대 절댓값)으로 두고, 수령 예상액은 목표 이익에 가산하지 않는다. 30일 미확보 시 사용 가능한 기간과 추정임을 표시한다. 정산 일정·표시 요율 자체가 없으면 비용 미확인이다. 6시간을 넘어 보유하면 실제 비용과 이후 예상 비용을 갱신하되, 최초 R 분모는 고정한다. 이 추정은 최대 펀딩 보장이 아니다.

과거 재생의 계획에는 당시까지 알려진 펀딩 정보만 사용한다. 나중에 확정된 실제 펀딩은 장부 정산에 사용할 수 있지만 과거 진입 여부 결정에는 사용할 수 없다. 과거 표시 요율이 없으면 그 시점 이전 확정 자료로 산출한 가정임을 기록하고, 그러한 계획 결과를 실시간 입력과 완전히 동일하다고 주장하지 않는다.

### 6.2 최초 목표와 경제성

체결 추정 가격에서 손절까지 거리 D=|P_e−S|로 정의한다.

- A·B: 최초 기준 목표는 P_e+d×1.5D, 다음 참고 목표는 P_e+d×3D.
- 진입 시점에 알려진 최근 120개 5분봉의 확정 pivot 중, 진입 가격 앞에 있는 가장 가까운 저항/지지가 최초 목표보다 가까우면 그 수준에서 0.05A 앞선 가격으로 최초 목표를 낮춘다.
- C: 위 최초 목표와 고정 박스 중간값 중 가까운 값을 사용한다. 다음 참고 목표는 반대쪽 박스 경계다.
- 알려진 구조 수준이 없으면 1.5D/3D는 ‘위험 거리 기준 투영값’으로 표시한다. 확인된 저항이나 도달 확률이라고 표시하지 않는다.
- 최초 목표에서 전량을 청산한다고 계산한 **비용 후 목표이익 / 비용 포함 계획손실**이 1.20 이상이어야 후보가 경제성 심사를 통과한다. 이는 승률을 반영한 기대수익이 아니다.
- 왕복 거래 비용의 추정값이 비용 포함 계획손실의 20%를 초과하면 COST_TOO_LARGE다. 최초 목표 손익비와 비용 비중의 탈락 수를 각각 보고한다.

비용 기준은 사전 고정 초기값이다. 신호가 적다는 이유로 실행 중 자동 완화하지 않는다. 변경이 필요하면 별도 가설·버전으로 검증한다.

### 6.3 위험 크기

연구용 기본 시드는 **가상의 1,000 USDT**, 1회 계획 위험은 **시드의 0.25%**로 시작한다. 이는 사용자의 실제 잔액·현재 위험 설정이 아니다. 0.50%는 같은 거래 경로에 대한 민감도 분석만 제공하며 기본값을 자동 상향하지 않는다.

~~~text
risk_budget = reference_equity × 0.0025
loss_per_BTC = |P_e - 예상 손절 체결가|
             + 진입 수수료/BTC + 손절 수수료/BTC
             + 보수적 예상 지급 펀딩/BTC
q = 수량 간격으로 내림(risk_budget / loss_per_BTC)
~~~

최소 주문 조건에 못 미치면 거래하지 않는다. 예상 손절 체결가에는 가정한 체결 오차를 포함한다. 급격한 가격 공백에서는 실제 손실이 계획값을 넘을 수 있으므로 ‘최대 손실 보장’이라고 표기하지 않는다.

레버리지는 손익 목표를 맞추는 변수로 사용하지 않는다. 표시 증거금은 q×P_e/선택 레버리지이며, 레버리지·증거금 방식이 확인되지 않으면 비워둔다. 참고 위험 기준 수량과 증거금을 구분한다. 계좌 상태와 상품별 유지증거금 구간이 없으면 강제청산 가격을 계산 완료로 표시하지 않는다.

통합 모의 장부의 기본 위험 한도는 다음과 같다.

- 동시 포지션 1개, 신규 진입 시 계획 위험 합계 시드 0.50% 이하.
- KST 일 시작 시점 대비 순자산 손실 1.00% 도달 시 그날 신규 진입 중지. 미실현 손익과 비용을 포함하고 기존 포지션의 위험 관리는 계속한다.
- 모의 자산 고점 대비 하락 5.00% 도달 시 전략 검토 상태. 자동으로 기준을 풀지 않는다.

참고 계산: 손실 거래가 비용 포함 −1R이고 시드 위험이 0.25%라면, 하루 7승 3패로 시드 +7%를 내려면 이긴 거래당 평균 약 +4.43R이 필요하다. 0.50% 위험이면 약 +2.43R이다. 단리·동일 위험 가정의 설명이며 달성 예측이 아니다. 승률만으로 목표 달성을 판단하지 않는다.

## 7. 보유 관리: 작은 역행과 구조 붕괴 구분

진입마다 원래의 F·S·I·ATR·목표·규칙 버전을 고정 저장한다. 이후 롤링 지지선이 바뀌었다는 이유만으로 과거 진입 근거를 덮어쓰지 않는다.

### 7.1 처리 우선순위

1. **손절 발생:** 지정한 가격 기준이 현재 유효 손절을 건드리면 즉시 위험 이벤트. 완료봉 추가 확인을 기다리지 않는다.
2. **원래 구조 무효화:** 진입 후 시작한 완료 5분봉 종가가 I를 불리한 방향으로 돌파하면 구조 종료 이벤트.
3. **부분 익절·추적 손절:** 실제 모의 체결 순서에 따라 반영.
4. **주의:** 상위 상태가 TREND에서 TRANSITION/RANGE로 바뀌거나 자료가 약해졌지만 손절·무효화 증거가 없는 경우. 최초 변화 때 한 번만 보낸다.
5. **유지:** 원래 구조가 유효하면 추적을 계속한다. RSI나 단기 가격 역행만으로 긴급 종료하지 않는다.

같은 봉에서 손절과 목표를 모두 건드린 경우에는 9절의 체결 순서 규칙을 적용한다. 자료 결측은 반전 증거가 아니며 DATA_DEGRADED 이벤트다. 진입 판정이 멈춰도 가능한 가격 기반 위험 감시는 계속한다.

### 7.2 수익 확대

- 최초 목표 체결 시 25% 부분 청산, 나머지 75% 추적이 기본 가설이다.
- 최초 목표 전에 손절을 본전으로 당기지 않는다.
- 최초 목표 이후 완료 5분봉마다 롱은 max(기존 손절, 잔여 수량의 비용 조정 본전, 진입 이후 완료봉 최고가−2×현재 ATR14)로 추적한다. 숏은 min과 최저가+2×ATR로 대칭 적용한다.
- 위 최고가·최저가는 진입 이후에 시작한 완료봉만 사용한다. 진입이 5분 구간 중간이면 그 구간의 진입 전 고가·저가를 추적 기준에 포함하지 않는다.
- 비용 조정 본전은 잔여 수량의 배분된 진입 비용·현재까지 발생한 펀딩·예상 청산 비용을 포함해 잔여 순손익이 0이 되는 가격으로 계산한다. 이미 실현한 부분 이익을 중복 사용하지 않는다.
- 새 손절은 새 상태 저장 시각 이후에만 유효하다. 과거 봉의 저가에 새 손절을 소급 적용하지 않는다.
- 새 손절이 현재 청산 가능 가격보다 이미 불리하게 통과된 상태이면 즉시 종료 이벤트로 처리하며, 불가능한 새 손절 주문이 존재하는 것처럼 기록하지 않는다.
- 다음 참고 목표 도달은 전량 종료 조건이 아니다. 추적 손절 또는 구조 무효화까지 잔여 수량을 관리한다.
- 6시간은 상태 재평가, 24시간은 장기 추적 안내 시점이다. 경과 시간만으로 청산을 지시하거나 장부에서 삭제하지 않는다.

연구 종료 시 아직 열려 있는 거래는 OPEN_AT_CUTOFF로 남기고 평가 시점 순자산에 시가평가한다. 종료 거래 수·승률에 억지로 포함하지 않는다.

### 7.3 가격 기준

LBank TP/SL에는 Last Price와 Mark Price 선택이 있다.[S1] v1 신호의 기본 관찰 기준은 LAST로 명시한다. MARK를 선택한 실사용 설정과의 동등성을 주장하려면 MARK 시계열도 확보해야 한다. Last OHLC로 Mark 손절을 재현했다고 보고하지 않는다. 강제청산 기준·실제 주문 체결과 참고 알람을 구분한다.

## 8. 상태·알림·저장

### 8.1 상태 모델

~~~text
DETECTED -> WATCHING(B만) -> READY -> PAPER_OPEN -> PAPER_PARTIAL -> PAPER_CLOSED
DETECTED/WATCHING/READY -> EXPIRED 또는 CANCELLED
어느 상태에서나 별도 health 상태: HEALTHY / DATA_DEGRADED / DELIVERY_DEGRADED
~~~

A·C는 DETECTED에서 READY로 갈 수 있다. READY는 조건이 성립했다는 뜻이며 사용자 체결을 뜻하지 않는다. 알림 전송 성공도 사용자 체결 확인이 아니다.

각 신호에 signal_id, setup_id, rule_version, data_version, cost_model_version, parent_signal_id, source_times, state, frozen_thesis, expires_at, event_sequence를 저장한다. 중복 방지 키는 상품·전략·방향·원본 후보 봉 시각·규칙 버전이다. 같은 추세 구간의 겹치는 거래는 같은 episode_id로 묶어 검증 독립성을 과장하지 않는다.

### 8.2 알림 정책

- 기본 발송은 진입 조건 성립, 취소·만료, 손절·구조 무효화, 부분 익절, 유의미한 추적 손절 변경, 데이터·전송 장애다.
- 15분마다 ‘가격 기록 갱신’만 보내는 상태 알림은 기본 꺼짐이다. 원시 상태와 탈락 이유는 내부 저장한다.
- 진입 수신자용 알림과 검증 운영 메시지를 구분한다. 새 버전이 모의 단계이면 제목 맨 앞에 ‘모의 검증’을 표시한다.
- 추적 손절은 최소 0.25×진입 ATR 이상 개선되거나 본전 전환 때 발송한다. 내부 손절 갱신은 그보다 작은 변화도 저장한다. 긴급 이벤트에는 이 기준을 적용하지 않는다.
- 한국어로 표현하고, ‘주의’, ‘무효화’, ‘손절’, ‘유효시간 만료’를 혼용하지 않는다.
- 조건 점수를 승률로 쓰지 않는다. v1은 임의의 95/100 같은 표시를 만들지 않는다.

진입 메시지의 필수 필드:

~~~text
[모의 검증 | BTCUSDT 선물 | LONG | 추세 되돌림]
판정 시각(KST) / 데이터 시각 / 유효 종료 시각
진입 허용 범위 / 현재 체결 추정 가격
손절 가격과 LAST 또는 MARK 기준
5분 종가 기준 구조 무효화 가격
1차 목표: 25% / 잔여 75% 추적 방식 / 다음 참고 목표
가상 시드·계획 위험 USDT와 %·참고 수량
비용 후 목표 손익비 / 비용 확인 수준
진입 근거 한 문장 / 현재 상충 근거 또는 자료 부족
signal_id / rule_version
~~~

실제 숫자 없는 예시 문구를 현재 시장의 진입 알림으로 보내지 않는다.

### 8.3 전송 내구성과 복구

신호·상태 이벤트·outbox를 하나의 데이터베이스 트랜잭션으로 저장한다. 별도 발송기가 outbox를 전송하고 성공 응답을 기록한다. 같은 이벤트 재시도는 같은 idempotency key를 사용한다. 외부 전송기가 멱등성을 지원하지 않으면 응답 유실 때 중복 가능성을 기록하고, 정확히 한 번 전달됐다고 보장하지 않는다.

손절·무효화는 전송 실패 후 가격이 반등해도 지우지 않는다. 최초 발생 시각·가격과 현재 상황을 함께 재전송한다. 진입 알림은 재시도 시 유효시간을 다시 확인한다. 만료된 진입을 신규 진입처럼 뒤늦게 보내지 않는다.

지속 저장은 기존 데이터베이스가 있으면 재사용한다. 없다면 단일 프로세스 기준 SQLite WAL과 영속 디스크로 시작한다. 원시 봉은 기간별 파일이나 테이블로 보존하고 메모리 deque를 유일한 연구 저장소로 삼지 않는다. 한 시점에 판정 writer는 1개만 실행한다.

## 9. 과거 재생과 모의 체결

### 9.1 같은 엔진 사용

실시간과 과거 재생은 동일한 순수 함수로 지표·후보·계획·상태를 계산한다. 과거 검증만 따로 유리한 규칙을 사용하지 않는다. 시간 진행과 체결 자료 공급만 어댑터로 바꾼다.

~~~text
입력 이벤트 도착
  1. 출처·시각·중복 검증 후 저장
  2. 활성 포지션의 손절·체결·펀딩·구조 종료 처리
  3. 완료봉일 때 지표와 시장 상태 갱신
  4. 기존 감시 후보의 취소·만료·확인 처리
  5. 새 후보 생성 -> 가격·비용·위험 심사 -> 충돌·중복 처리
  6. 상태와 발송 이벤트를 원자적으로 저장
발송기는 유효시간을 확인해 별도로 전송
~~~

같은 시각에 여러 봉이 닫히면 1분 원자료 검증 → 5분 완료 확정 → 15분 집계 → 지표/시장 상태 → 전략 판정 순서다. 순서를 고정하고 중복 실행하지 않는다. 과거 입력을 다시 실행하면 신호·상태 이벤트 hash가 같아야 한다.

### 9.2 체결 시각과 가격

- 틱·호가 기록이 있으면 알림 이후 첫 유효한 체결 가능 호가로 재생한다. 자동 즉시 체결과 사용자 수동 반응 지연 시나리오를 별도로 둔다.
- 과거 자료가 1분 OHLC뿐이면 기본 지연 60초, 추가 스트레스 지연 120초로 둔다. 신호 시각+지연 이상인 최초 1분봉 시가를 기준으로 불리한 체결 오차를 반영한다. 신호를 만든 봉의 종가 체결은 인정하지 않는다.
- 진입 유효시간 120초를 초과하면 미체결이다. 경계 시각과 같으면 허용하되 해당 시가가 진입 범위 안에 있어야 한다.
- 과거 호가가 없을 때 슬리피지 가정은 편도 2bp, 스트레스 5bp와 10bp로 각각 보고한다. 이는 LBank에서 실측한 비용이 아니다. 수수료는 별도로 반영한다. 실제 호가 자료가 있으면 호가 차이와 중복 계산하지 않는다.
- 일단 진입 범위를 놓친 뒤 나중에 유리한 가격이 왔다고 같은 신호의 체결을 되살리지 않는다. 지정 지연 시점에 조건이 안 맞으면 그 시나리오는 미체결로 끝낸다.
- 손절 주문은 손절 가격 그대로 체결된다고 고정하지 않는다. 롱은 갭 하락 시 더 낮은 시가/호가, 숏은 더 높은 시가/호가에 체결 오차를 더한다.
- 가격이 목표에 닿았다는 것과 지정가 주문 체결은 다르다. v1 모의 목표 청산은 시장가 청산 가정으로 수수료·체결 오차를 적용한다.

### 9.3 봉 안의 순서가 불명확한 경우

1. 5분 안의 순서는 가능하면 1분 원본으로 판별한다.
2. 같은 1분봉 안에서 손절과 목표가 모두 닿으면 기본 성적은 불리한 손절 우선으로 계산한다. 유리한 순서의 결과도 별도로 구해 결과 범위를 표시한다.
3. 부분 익절 이후 새 손절이 생긴 봉 역시 같은 원칙을 적용한다. 봉 고가를 먼저 알고 봉 저가에 새 추적 손절을 적용하는 식으로 최상의 순서를 선택하지 않는다.
4. 실시간 진입이 분봉 중간에 이뤄졌다면 그 분봉의 전체 저가·고가로 진입 이후 손절/익절 발생을 확정하지 않는다. 진입 이후 틱이 없으면 AMBIGUOUS_INTRABAR로 표시한다. 분 시작 체결을 사용하는 과거 재생은 전체 봉을 평가할 수 있다.
5. 순서 불명확 거래의 수·손익 범위·전체 결과 민감도를 반드시 보고한다. 불명확 거래를 단순 삭제한 승률을 대표 성과로 쓰지 않는다.

### 9.4 데이터 누락과 비용 미확인

포지션 보유 중 가격 구간이 누락되면 DATA_CENSORED다. 마지막 가격에서 수익 실현한 것으로 끝내지 않는다. 펀딩 정산을 지났는데 실제 정산 자료가 없으면 FUNDING_UNVERIFIED다.

이러한 거래는 원시 기록과 시가평가 정보를 남기되, 검증된 순손익 거래 집합에 섞지 않는다. 동시에 **제외 건수·가능 손실 영향 때문에 전체 성과를 판정할 수 있는지**를 보고한다. 제외한 뒤 남은 양수 거래만으로 합격시키지 않는다. 통합 장부가 손익을 확정할 수 없으면 해당 검증 구간은 성과 합격 판단 불가다.

## 10. 성과 검증과 채택 기준

### 10.1 자료 분할과 실험 수

- 목표 자료는 최근 90일의 동일 상품 원본 1분봉·5분봉 및 비용 자료다. 이는 이미 확보됐다는 주장이 아니다.
- 확보 가능하면 시간순으로 개발 45일, 검토 15일, 최종 봉인 시험 30일로 나눈다. 각 구간 앞의 워밍업은 특징 계산에만 쓰며 거래 성과에는 포함하지 않는다.
- 90일보다 짧으면 실제 구간을 공개한다. 개발·시험용으로 같은 거래를 중복 사용하지 않는다. 최종 시험의 아래 최소 증거 요건이 안 되면 EVIDENCE_INSUFFICIENT다.
- 최종 시험에 들어가기 전에 규칙·매개변수·비용 가정·후보 우선순위·판정 기준을 저장하고 hash를 고정한다.
- 초기 실험 예산은 **정의된 세 전략의 기본형 3개와 변경형 최대 3개**, 총 6개 설정이다. 수천 개 조합을 탐색하지 않는다. 통합 포트폴리오의 우선순위도 결과를 본 뒤 바꾸지 않는다.
- 검토 구간까지 보고 최종 후보를 고를 수 있다. 최종 시험 결과를 보고 다시 수정하면 새 버전이며, 같은 시험을 독립 검증이라고 재사용하지 않는다.
- 가격·시장 상태·도미넌스·pivot은 각 시점에 알려진 값만 사용한다. 정정된 미래 정보는 별도의 사후 진단에만 쓴다.

많은 규칙 중 과거에 잘 나온 것만 고르면 성과가 부풀려질 수 있다. 후보 수와 실패 결과까지 기록하는 이유다.[S5]

### 10.2 두 장부

**전략 연구 장부:** A·B·C의 가설을 각각 관찰한다. 겹치는 거래를 포함할 수 있지만 겹침·같은 episode를 표시한다.

**통합 운용 장부:** 실제 알림 우선순위·중복 억제·동시 위험 한도·미체결·일 손실 중지를 적용한 하나의 가상 계좌다. 사용자에게 제시할 시드 기준 성과는 이 장부에서 산출한다. 세 장부의 수익을 단순 합산하지 않는다.

사용자 실제 계좌 장부는 별도다. 사용자가 체결 내역을 제공하지 않으면 신호 성적을 실제 투자 수익으로 표현하지 않는다.

### 10.3 필수 성적표

| 영역 | 반드시 제시할 값 |
|---|---|
| 표본 | 후보·READY·모의 체결·종료·미체결·중복 억제·불명확·자료 누락 건수 |
| 수익 | 비용 후 순손익, 평균 net R, 손익비, 승률, profit factor |
| 위험 | 시가평가 포함 최대 낙폭, 최장 연속 손실, 최악의 하루, 비용 초과 손실 |
| 가용성 | 일평균·중앙값·최솟값 알림 수, 무신호 일수, 최대 무신호 시간 |
| 장세 | 상승·하락·횡보·전환, 롱·숏, 전략별 결과와 표본 수 |
| 실행 | 지연·체결 오차별 성과, 오래된 신호·중복·전송 실패 |
| 목표 | 시드 기준 일 순수익 7% 이상 일수/전체 관찰 일수, 일 수익률 분포 |

일 수익률=(KST 하루 종료 순자산−시작 순자산−순입금)/시작 순자산. 가상 계좌는 입출금 0이다. 미실현 손익·수수료·펀딩을 포함한다. 거래 없는 날도 7% 달성률 분모에 포함한다. 증거금 ROI와 시드 수익률은 별도 열이다.

PF=양의 거래 순손익 합 / 음의 거래 순손익 절댓값 합. 손실 거래가 0이면 무한대로 합격시키지 않고 표본 부족으로 판단한다. R의 분모는 진입 시 고정한 비용 포함 계획 위험액이다.

### 10.4 사전 고정 판정

아래 수치는 **연구 후보를 분류하기 위한 제안 기준**이며, 미래 수익을 보장하는 통계 법칙이 아니다. 통과를 쉽게 하려고 결과를 본 뒤 바꾸지 않는다.

| 등급 | 기준 | 허용되는 표현 |
|---|---|---|
| ENGINEERING_READY | 12절의 필수 동작 시험 통과, 데이터·기록·복구 동작 확인 | ‘구현 및 기능 검증 완료’ |
| HISTORICAL_CANDIDATE | 봉인 시험 종료 거래 ≥50건, 거래가 있었던 서로 다른 KST 날짜 ≥20일; 비용 확인된 전체 구간; 기본 PF≥1.20, 평균 net R>0, 최대 낙폭≤5%; 5bp 체결 오차+120초 지연에서 총 순손익>0 | ‘과거 시험에서 후보 기준 충족’ |
| EVIDENCE_INSUFFICIENT | 표본·시장 상태·원자료·비용 중 충분하지 않은 항목 존재 | ‘자료 또는 관찰 부족’ |
| REJECTED | 검증 가능한 자료에서 위 경제성·위험 기준 미달 | ‘현재 규칙 폐기 또는 새 가설 필요’ |

봉인 시험에서 미실현 포지션을 포함한 총 순자산 성과도 양수여야 한다. 단기 종료 거래만 양수이고 열린 손실이 큰 경우 합격시키지 않는다. 10bp 스트레스는 별도 공개하며, 양수 여부를 기본 합격 조건으로 숨겨 추가하지 않는다.

95% 불확실성 구간은 거래별 무작위 섞기 대신 **KST 날짜별 거래 묶음을 3일 연속 블록으로 재표집**, 기본 2,000회·고정 seed로 구한다. 같은 장세·episode의 의존성을 완전히 제거하는 방법은 아니므로 한계를 기록한다. 평균 net R의 하한이 0 이하이면 ‘통계적 근거 약함’을 표시한다. 표본이 적은 장세의 결과를 전체 장세로 일반화하지 않는다.

실시간 모의 검증은 규칙 고정 이후 들어온 새 자료만 별도로 쌓는다. 1~2일의 결과에는 기능·체결 지연·실시간 일관성 확인이라는 의미를 부여한다. 검증 기간을 채우기 위해 의미 없는 거래를 생성하지 않는다. 과거 합격만으로 기존 운용을 자동 교체하지 않는다.

### 10.5 무신호 원인 보고

24시간 신규 READY가 0이면 다음 순서의 숫자를 산출한다.

~~~text
정상 수신 봉 수
-> 시장 상태별 봉 수
-> A/B/C 패턴 발생 수
-> 가격 범위/목표 거리/비용/위험 각각의 탈락 수
-> 중복·충돌·유효시간 만료 수
-> READY 수
-> 발송 성공/실패 수
~~~

모든 공통 심사를 평가해 탈락 이유의 비트 집합을 저장하고, 최초 탈락 단계 수와 복수 사유 빈도를 함께 보고한다. 0건의 원인이 시장 기회 부족인지, 데이터 문제인지, 과도한 조건인지, 발송 장애인지 구분한다. 무신호만으로 횡보라고 결론짓거나 임계값을 자동으로 낮추지 않는다.

### 10.6 기존 설계와의 교체 판정

대조군은 구현 착수 시 확인한 최신 기존 코드의 고정 commit이다. 기존 시드·레버리지 차이로 새 설계의 성과가 좋아 보이지 않도록 비교용 계좌는 둘 다 시드 1,000 USDT, 동일 0.25% 계획 위험, 동일 수수료·슬리피지·지연으로 맞춘다. 실제 과거 운영 결과는 별도 참고 열에만 둔다. 비교 과정에서 기존 전략의 진입·청산 규칙을 몰래 고치지 않는다.

정규화된 위험 모델 연결로 기존 동작에 차이가 생기면 그 범위와 이유를 보고한다. 기존 코드가 같은 자료로 재현되지 않으면 기존 대비 우위 판정은 불가하고 새 설계 자체의 검증 결과만 제시한다.

**교체 후보가 되려면 다음을 모두 확인한다.**

- ENGINEERING_READY와 HISTORICAL_CANDIDATE를 충족한다.
- 같은 봉인 시험 기간의 통합 계좌 최종 순자산 증가가 기존보다 크고, 최대 낙폭은 기존 이하이다. 열린 포지션을 포함한다.
- 기본 비용뿐 아니라 5bp·120초 스트레스에서도 양수이며, 그 조건의 기존 결과보다 낫다.
- 기존 READY가 20건 이상일 때 새 READY가 기존의 80% 미만이면 가용성 감소를 별도 의사결정 항목으로 올린다. 성과가 좋다는 이유로 빈도 감소를 숨기거나 자동 교체하지 않는다. 기존 READY가 20건 미만이면 비율만으로 가용성 개선을 판단하지 않는다.
- 날짜별 순수익 차이를 같은 날짜 묶음으로 재표집한 95% 구간을 표시한다. 개선 차이의 하한이 0 이하이면 ‘개선 관측, 우위 근거 불충분’으로 적는다. 이 경우 기존보다 확실히 우수하다고 보고하지 않는다.

판정은 아래처럼 명시한다.

| 결과 | 보고와 다음 행동 |
|---|---|
| 구현 통과, 자료 부족 | 구현 산출물 제공, 부족한 증거와 수집 방법 제시 |
| 자체 기준 통과, 기존 대비 열위 | 기존 교체 보류; 실패 원인을 새 가설로 분리 |
| 개선 관측, 불확실성 큼 | 새 자료의 모의 관찰 후보; 우수성 확정 표현 금지 |
| 개선·위험·가용성 근거 확보 | 교체 후보 보고; 해당 대화의 운용 전환 지시에 따라 적용 |

최종 보고서 첫 페이지에는 ‘좋아진 점 / 나빠진 점 / 아직 모르는 점’을 각각 실제 숫자로 적는다. 분석으로 해결한 문제와 아직 풀리지 않은 거래 성과 문제를 구분한다.

## 12. 필수 검증 사례

아래는 손익·신호·운영 상태를 바꿀 수 있는 실제 실패를 검증하는 항목이다. 단순한 문구·함수 호출 횟수만 확인하는 시험을 늘리지 않는다.

1. 같은 BTC/USDT 이름이어도 현물·역선형·다른 거래소 자료는 거부된다.
2. 진행 중인 봉의 큰 움직임은 완료 전 신호를 만들지 않는다.
3. pivot은 오른쪽 두 봉이 끝나기 전에는 이용할 수 없다.
4. 누락 1분봉을 정적 가격으로 채워 손절 회피나 목표 도달을 만들지 않는다.
5. 동일 완료봉을 여러 번 받아도 신호·체결·주의 이벤트가 중복되지 않는다.
6. 원래 구조 유지 중 단기 역행은 구조 종료가 되지 않는다. 원래 I 종가 이탈은 종료된다.
7. 현재 손절을 건드린 가격이 반등해도 손절 이벤트가 취소되지 않는다.
8. 부분 익절 후 바뀐 손절은 변경 시각 이전의 봉에 적용되지 않는다.
9. 동일 봉 내 손절·목표 동시 도달, 갭, 분봉 중간 진입을 보수적으로 처리한다.
10. long/short 비용·수량·부분 청산·펀딩 부호를 독립적인 수치 예제로 대조한다.
11. 한 봉에서 여러 전략이 생겨도 통합 계좌 위험과 거래 수가 중복되지 않는다.
12. 전송 실패·응답 유실·프로세스 재시작 후 긴급 이벤트와 미종료 포지션이 복구된다.
13. 만료된 진입은 전송 재시도로 부활하지 않는다.
14. 6시간 경과는 검토 이벤트만 만들며 강제 종료하지 않는다.
15. 실시간 기록을 재생했을 때 동일 규칙의 후보·상태 전이가 일치한다. 차이는 자료 도착·체결 어댑터 차이로 설명되어야 한다.
16. 하루 순자산 손실 한도·전체 낙폭 한도가 새 진입만 제한하고 기존 위험 관리를 중단시키지 않는다.
17. 검증 자료 결측·미확인 펀딩·열린 손실을 제외해서 성과가 인위적으로 좋아지지 않는다.
18. mock 알림·봉 갱신·비용 가정 변경을 종료 거래 표본으로 세지 않는다.

시험 통과는 코드의 명세 준수를 확인한다. 전략의 수익성을 입증하는 것으로 보고하지 않는다.

## 13. Sol 6.1 실행 지침과 크레딧 예산 관리

### 13.1 착수 때 할 일

1. 이 문서를 먼저 읽고, 현재 작업 중지 여부와 실제 저장소·원본 데이터 접근을 확인한다.
2. 기존 기능 중 어댑터·저장·발송·복구를 재사용할 부분을 한 번만 조사한다. 읽은 자료 목록과 결론을 인수인계 파일에 저장한다.
3. P0 데이터 보고서를 작성하고, 확인되지 않은 API·수수료·상품 단위를 표시한다. 미확인 API 주소를 추측해 구현 완료로 보고하지 않는다.
4. 기존 전략과 충돌하지 않는 별도 구현 경계에서 P1·P2를 진행한다. 운영 전환과 알림 재개는 해당 대화의 최신 사용자 지시에 따른다.

### 13.2 짧은 작업 단위

| 작업 묶음 | 주 담당 | 종료 산출물 |
|---|---|---|
| 설계 고정 | Astra, 이 문서 | 규칙·검증 기준·확인 과제 |
| P0·어댑터·저장 | Sol 6.1 | data_manifest와 연결 검증 결과 |
| P1·장부·재생 | Sol 6.1 + Python | 구현·필수 시험 결과 |
| P2 비교·모의 연결 | Sol 6.1 + Python | 평가표·제외 사유·고장 시나리오 결과 |
| 최종 중요한 모순 검토 | 필요할 때 Astra | 변경 코드·요약표·대표 실패 5건에 대한 검토 |

매 작업 묶음이 끝나면 결과와 다음 작업을 정리하고 멈춘다. ‘모든 지식을 더 찾아서 완벽해질 때까지 계속’ 같은 종료 없는 작업으로 확장하지 않는다. 이미 답이 난 문제를 다른 표현으로 반복 검색하지 않는다.

상시 운영 코드에는 LLM 호출을 넣지 않는 것이 v1의 원칙이다. 데이터 수집·지표 계산·매매 조건·모의 장부·발송 문구는 결정적 코드로 처리한다. 모델이 읽을 보고서는 요청 시 또는 명시적으로 승인된 검토 주기에만 만든다. 매 15분마다 AI에게 동일 로그를 다시 해석시키지 않는다.

실험을 더 늘려야 한다면 기존 6개 결과와 추가 가설의 이유부터 제시한다. 단순 수치 계산·대량 재생은 Python에서 실행하고 원시 로그 전체를 대화에 반복 출력하지 않는다. 비용 절감이 필요할 때는 먼저 중복 입력·무한 탐색·불필요한 모델 호출을 줄인다.

크레딧 지출은 사용량 화면에서 단계 사이에 확인한다. 모델이 계정 잔액을 실시간 계량하거나 자연어 예산 요청만으로 확실한 자동 결제 상한을 적용한다고 약속하지 않는다. 서버·데이터 사용료는 모델 크레딧과 별도다.

### 13.3 최종 전달 파일

- 구현 코드와 설정, 설치·실행 설명.
- data_manifest: 상품·공급원·기간·결손·비용 자료·hash.
- experiment_manifest: 실험 6개 이내의 전체 기록, 사전 고정 시각·버전.
- comparison_report: 신규 세 전략·통합 장부·기존 전략을 같은 자료·비용·위험 기준으로 비교.
- alert_examples: 진입·주의·무효화·부분 익절·장애 메시지 예시.
- handoff: 완료·보류·미확인 항목과 재현 명령. 실패 결과를 포함한다.

사용자가 바라는 일일 7%와 실제 측정 성과 사이의 차이는 숫자로 보고한다. 목표에 미달하면 위험을 늘려 숫자를 맞추지 않는다.
