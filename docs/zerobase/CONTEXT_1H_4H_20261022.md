## 요청과 시간대별 역할

4시간봉 방향과 주요 지지·저항을 먼저 참고 정보로 기록하고, 손익·낙폭·알람 빈도를 비교한다. 사용자의 추가 요청에 따라 1시간봉도 포함한다.

| 시간대 | 역할 | 이번 변경에서의 사용 |
| --- | --- | --- |
| 4시간 | 큰 방향과 상대적으로 긴 구간의 가격 구조 | 방향, 지지·저항 후보, 신호 방향과의 관계 기록 |
| 1시간 | 큰 방향 안의 조정·반등과 가까운 가격 구조 | 같은 항목 기록, 4시간 방향과 일치·반대·혼합·미확인 구분 |
| 15분 | 기존 ZB 시장 상태 분류 | 기존 로직 유지 |
| 5분 | 기존 세 전략의 진입 후보와 무효화 판단 | 기존 로직 유지 |
| 1분 | 기존 체결 지연·청산·위험 관리 재생 | 기존 로직 유지 |

예를 들어 4시간 상승·1시간 하락은 두 방향이 다르다는 관찰이다. 이를 자동으로 매수 기회나 추세 반전으로 확정하지 않는다. 모든 시간대의 방향 일치를 필수 조건으로 요구하지 않는다.

## 완료 봉·시점·가격 구조

- 기존 상품 검증을 통과한 LBank BTCUSDT USDT 선형 무기한 선물의 원본 5분봉을 사용한다. 같은 구간의 1분봉 합성과 가격·거래량 교차 확인을 통과해야 참고 봉에 포함한다. 가격 단위 정보가 없어 교차 확인할 수 없는 경우도 임의로 통과시키지 않는다.
- 연속 12개로 1시간봉, 연속 48개로 4시간봉을 만든다. 경계는 UTC 기준이다. 4시간봉 시작은 UTC 00·04·08·12·16·20시, KST 09·13·17·21·01·05시다.
- 미완료 봉, 누락 봉, 수신 전에 알 수 없었던 봉을 사용하지 않는다. 누락을 다른 거래소·현물·가격 표본으로 채우지 않는다. 신뢰할 수 없는 완성 구간 이후에는 연속 이력을 다시 쌓는다.
- 각 시간대의 방향은 기존 EMA20·EMA50·ATR 및 효율비율 기반 상태 분류 함수를 재사용한다. 이는 새 시간대에서 수익성이 검증된 규칙이라는 뜻이 아니다.
- 각 시간대의 완료 봉 150개가 필요하다. 1시간은 150시간, 4시간은 600시간(25일)의 과거 이력이다. **지금부터 25일을 기다려야 한다는 뜻은 아니다.** 검증된 과거 봉이 있으면 사전 적재할 수 있다. 이번 변경에는 자동 과거 자료 수집기가 포함되지 않는다. 자료가 부족하면 `UNKNOWN`을 기록하고 이 이유로 기존 진입을 차단하지 않는다.
- 최신 160개 봉을 보관한다. 다음 완료 시각까지는 직전 완료 봉을 사용하며, 다음 봉 수신 유예 15초를 넘으면 `UNKNOWN`으로 표시한다.
- 지지·저항 후보는 최근 120개 봉 범위의 확정 고점·저점에서 찾는다. 좌우 2개 봉으로 확인하며 오른쪽 2개 봉이 완료·수신된 뒤에만 사용한다. 고점·저점 발생 시각과 확인 가능 시각을 함께 저장한다.
- 현재 신호 가격 아래에서 가장 가까운 구조 가격을 지지 후보, 위에서 가장 가까운 구조 가격을 저항 후보로 기록한다. 원래 고점인지 저점인지도 보존한다. 이는 실제 매수·매도 주문의 존재, 지지·저항 강도 순위, 돌파 후 역할 전환의 확정이 아니다. 후보가 없거나 가격과 정확히 같으면 임의의 위·아래 후보를 만들지 않는다.

## 기록과 메시지

`Engine(..., context_mode='record')`가 기본이며 `off`는 비교용이다.

- `DETECTED` 당시의 1시간·4시간 상태를 후보 ID별로 고정한다. 방향, 봉 종료·수신 시점, 자료 수, 지지·저항 후보, ATR 거리, 진입 방향과의 관계가 포함된다.
- `READY` 메시지에 한국어 참고 설명을 붙인다. 상태가 반대이거나 미확인이어도 진입 계획, 수량, 손절, 목표가, 추적 규칙을 바꾸지 않는다.
- 참고 봉, 진행 중인 집계 구간, 후보 당시의 고정 정보를 장부 스냅샷에 포함한다. 기존 스냅샷 복원 시 없는 과거 정보를 만들어 넣지 않고 빈 참고 이력으로 시작한다.
- 이 모듈은 수집기·주문·메시지 발신을 시작하지 않는다. 현재 운영의 모의 알림 중지 및 배포 설정도 변경하지 않는다.

출력 형태:

```text
상위 흐름 참고 · 진입 허가/차단 조건 아님
4시간: 상승 / 지지 후보 … / 저항 후보 …
1시간: 하락 / 지지 후보 … / 저항 후보 …
1시간·4시간 방향이 다릅니다. 조정/반등 여부를 관찰하며 방향 전환을 확정하지 않습니다.
```

## 비교 방법과 해석

`lbank_zb.compare_context`는 같은 입력·비용 가정·체결 지연으로 ZB의 `off`와 `record`를 각각 재생한다. 외부 API 호출이나 알림 발신은 없다.

```bash
python3 -m lbank_zb.compare_context --input native.jsonl --scenario costs.json --latency 60 --output context_comparison.json
python3 -m lbank_zb.replay --input native.jsonl --scenario costs.json --context-mode record --output replay.json
```

입력과 비용 파일 형식은 기존 재생기와 같다. 검증된 동일 상품의 정규화된 1분봉·원본 5분봉과 명시적인 비용 가정이 필요하다. 비용 파일을 생략하면 기존과 같이 비용 미확인으로 처리한다.

1. 신호·거래 사건에서 설명 문구와 참고 특징만 제외한 해시를 비교한다. 가격·수량·판단·사건·시각이 같아야 한다.
2. 전체 포트폴리오의 비용 가정 후 모델 NAV 변화, 봉 수신 사건마다 측정한 최대 낙폭, 후보·준비 신호·진입·종료 수와 일평균 빈도를 비교한다. 평가 가격은 수신된 봉 중 가장 최신 종료 시점의 종가이며, 같은 시점에는 1분봉을 우선한다. 늦게 온 과거 봉으로 평가 가격을 되돌리지 않는다. 빈도의 분모는 입력에 포함된 준비 기간과 무거래일을 포함하는 KST 달력 일수다. 낙폭은 틱 단위나 봉 내부의 최대 낙폭이 아니다.
3. 원래 발생한 거래를 1시간, 4시간, 두 시간대 조합별로 나누어 관찰한다. 일치·반대·횡보·전환·미확인 그룹의 후보 수, 진입 수, 모델 종료 손익, 평균 순 R을 기록한다. 미확인 자료나 손익이 불확실한 거래를 숨기지 않는다.
4. 그룹별 손익은 **원래 포트폴리오의 사후 분류**다. 특정 그룹을 제외한 가상 전략의 손익이나 낙폭으로 제시하지 않는다. 그룹별 포트폴리오 낙폭은 `null`이다. 차단·가점·수량 조절을 나중에 도입한다면, 변경 규칙을 사전에 고정하고 자금·동시 보유·일일 중지까지 전체 재생해야 한다.

이번 변경은 참고 기록만 추가하므로 거래 손익·낙폭·빈도 차이가 0인 것이 정상이다. 실거래 기대 수익이 좋아졌다는 뜻은 아니다. 비용·펀딩 원본 검증 및 전체 연동이 미완료이므로 `verified_net=null`, `performance_claim=false`를 유지한다. **이 비교는 기존 운영 전략 대 ZB 성능 비교와도 별개다.**

결과에는 입력 사건 해시, 출처 표기, 기간, 비용 가정, 설정, 지연, 참고 정보 매개변수, 코드 파일 SHA256을 남긴다. 새로운 진입 변형을 추가하거나 기존 전략 탐색 예산을 늘리지 않는다.

- 낙폭의 별도 수치 예제, 늦게 온 과거 봉의 평가 가격 덮어쓰기 방지, 반복 재생 해시 및 장부의 기록 모드 불일치 거부.

## 6.1방 인수인계

별도 브랜치의 변경을 검토한 뒤 최신 연구 브랜치에 통합한다. 공유 `HANDOFF.md`, 운영 설정, 발신 중지 파일은 이번 변경에서 수정하지 않는다. 현재의 운영 배포·원본 자료 연결·실제 비용과 펀딩 연결을 완료했다는 주장도 하지 않는다.

다음 실제 자료 비교에서 먼저 두 시간대 자료 충족률과 `UNKNOWN` 비율을 확인한다. 그 후 같은 관측 기간·동일 비용으로 전체 결과와 상태별 결과를 함께 제시한다. 자료를 뒤늦게 확보해 과거 알람 당시 알고 있었던 것처럼 기록하지 않는다. 과거 재생 결과와 운영 시점 관측 기록을 구분한다.
