## 2. 사용자에게 제공할 최종 결과

모든 발송 신호에는 다음 하나의 거래 카드를 남긴다.

| 항목 | 필수 내용 |
|---|---|
| 언제 | 구조를 처음 알 수 있었던 시각, 후보·확인·발송 요청·Telegram 수락 시각 |
| 어디서 | 실제 관측 진입가/허용 구간, 고정 구조 기준점, 기준점에서의 이동 거리 |
| 왜 그 방향 | 관측한 반전/돌파/재시험 사실, 아직 성립하지 않은 근거 |
| 왜 그 목표 | 첫 장벽과 확정 시각, 완충 폭, 비용 후 목표 공간, 구조 손절 |
| 언제 무효 | 가격·구조·유효기간별 명시적 취소 조건 |
| 이후 | TP1/TP2·손절 선행 순서, 5/15/30/60분 결과, 최대 6시간 종료 결과 |
| 비교 | 기존/신규 공통·제외·추가 신호, 포착·발송 시차, 같은 비용의 손익 |
| 한계 | 봉 공백·동일 봉 순서 불명·체결 미확인·모형 비용 여부 |

실제 계정 체결과 잔고를 확보하지 않았다면 결과를 **관측 가격 기반 모형 손익**으로 표시한다. 당시 알려진 내용과 사후 분석은 별도 칸에 기록한다. 확률 검증 전에는 조건 점수를 승률 또는 정확도로 표시하지 않는다.

## 3. 진입 판단: 방향·위치·목표를 함께 설계

### 3.1 구조 목표를 먼저 정하고 허용 진입가를 역산

기존 `observed_target_room`과 확정 피벗 계산을 재사용한다. 각 피벗에는 봉 시작뿐 아니라 오른쪽 확인 봉이 실제 수신돼 확정된 `known_at`을 추가한다. 미래 봉으로 알게 된 고저점은 과거 신호에 사용할 수 없다.

1. 현재까지 알려진 무효화 기준 A와 가장 가까운 진행 방향의 미돌파 장벽 B를 찾는다.
2. 손절 S는 A 밖에 구조·변동성 완충을 두어 정한다. 목표 T1은 B 앞에 틱·스프레드 완충을 두어 정한다.
3. T1까지의 비용 후 수익과 S까지의 비용 포함 손실로 진입 허용 구간을 역산한다. 구조 목표가 계산상 필요한 목표에 못 미치면 `room_insufficient`이다.
4. 손익비를 맞추려고 T1을 B 너머로 옮기거나 S를 구조 안쪽으로 당기지 않는다. 상위 방향 일치로 미돌파 장벽을 없는 것으로 취급하지 않는다.
5. 가격이 좋은 진입 구간을 벗어났다면 추격하지 않고 유효 구조가 남은 동안 재시험을 내부 감시한다. 지지·저항이 실제로 돌파되고 재시험된 새 근거가 생기면 새 사건을 만든다.
6. 장벽 미발견은 `room_unknown`이다. “장벽 없음”으로 표현하지 않는다. 신규 설계 모드에서는 독립 근거 없는 수치 목표를 만들지 않고 내부 관찰로 남긴다. 이로 인한 기회 손실을 별도로 측정한다.

방향 d∈{+1,-1}, 양수 수량 Q일 때:
- 단위 목표 순익 = d×(T−E) − 진입/청산 수수료 − 불리한 슬리피지 − 펀딩 비용.
- 단위 손절 손실 = d×(E−S) + 진입/청산 수수료 + 불리한 슬리피지 + 펀딩 비용.
- 비용 후 RR = 목표 순익 / 손절 손실. 기존 최소 1.5를 유지한다.
- Q는 비용 포함 손절 손실에 대한 기존 위험 예산과 증거금 한도 중 더 작은 허용 수량으로 산출하고 최소 수량·수량 단위를 검증한다.
- 비용은 가격·실제 보유 시간에 따라 달라질 수 있으므로 단순 고정 목표 거리로 RR을 대체하지 않는다. 부분 청산 비용은 청산된 수량에 한 번씩만 적용한다.

비용 미검증 구간은 기존 모형 가정과 불리한 비용 시나리오를 명시한다. 펀딩이 확인되지 않았으면 실제 순익으로 보고하지 않는다. 계정 위험·증거금·일 한도는 이번 설계에서 늘리지 않는다.

### 3.2 반전과 추세 재개의 경로 분리

| 경로 | 그 시점에 관측해야 할 근거 | 방향을 정하는 방식 |
|---|---|---|
| 초기 반전 | 이미 알려진 지지·저항 이탈 후 회복, 완료 1분봉의 회복 구조, 그 구조의 작은 반대 고저점 돌파 | 회복한 구조 방향. 과거 5/15분 누적 수익률이 같은 방향으로 커질 때까지 일괄 대기하지 않는 실험 |
| 첫 돌파 재시험 | 사전 장벽 돌파 → 첫 재시험 유지 → 재시험 고저점 재돌파 | PR #21의 완료 구조+현재가 경로를 독립 실험으로 재사용 |
| 기존 추세 눌림 | 기존 구조가 유지되고 눌림 후 재개, 아직 유효한 목표 공간 | 운영 capture를 대조군으로 유지 |

초기 반전은 새 가설이지 검증된 전략이 아니다. 기존 RSI·EMA 정렬을 모두 필수로 유지한 채 이름만 “초기 반전”으로 바꾸지 않는다. 해당 경로에서는 RSI·5/15분 추세를 우선 설명 변수로 기록하는 별도 실험을 한다. 반대 추세에서의 실패율·거짓 회복을 따로 평가한다. 하드 데이터·비용·구조 위험 검사는 유지한다.

확정 최저점·최고점을 실시간으로 알고 있었다고 가정하지 않는다. 사후 차트 변곡점과의 거리는 설명용이며, 실시간 포착 평가는 **실제 근거가 처음 사용 가능해진 시각**을 기준으로 한다.

### 3.3 고정 대기를 추가하지 않는 확인 실험

PR #21에도 최소 30초 관찰은 남아 있다. 이를 이미 제거했다고 보고하지 않는다.
- 후보가 될 때 근거가 모두 충족됐는지 먼저 기록한다.
- 별도 실험에서 완료 구조의 실제 재돌파·유지, 최신 관측가, 구조 미침범, 허용 진입 구간을 충족한 첫 평가 시점에 확인하도록 한다.
- 진전 확인을 위해 과도하게 가격이 이동해야만 통과하는 조건을 피한다. “관찰가보다 유리한 방향으로 일정 폭 이동”과 “원래 구조의 확인선 돌파”를 분리한다.
- 시간만 지나면 확인하거나 근거가 깨진 뒤 회복했다는 이유로 첫 손절 침범을 지우지 않는다.
- 현재가를 가짜 완료봉으로 추가하지 않는다. 관측되지 않은 틱도 보간하지 않는다.
- 실제 관측 지연·스프레드·호가 자료가 부족한 구간은 신속 확인의 체결 가능성 검증에서 제외 사유를 남긴다.

신규 확인 규칙은 무발송 비교만 먼저 수행한다. 이전 데이터로 불가능한 미세 시간 성능을 추정해 “몇 초 빨라졌다”고 확정하지 않는다.

### 3.4 목표 이후 관리

T1 이전에는 고정 무효화 근거를 유지한다. T1 일부 청산 이후의 나머지 수량은 기존 추적 정책을 별도로 비교한다. 목표 확대는 실제 다음 장벽 돌파 등 새로운 근거가 생겼을 때 이후 시점부터 적용하고, 최초 목표·손절 기록은 불변으로 둔다. 손절을 손실 방향으로 넓히지 않는다. 목표 도달만으로 전량 체결로 처리하지 않는다.

## 4. 알람 상태와 무알람 이유

상태: `observed → armed → triggered → qualified → send_pending → acknowledged → tracking → closed/unknown`.
별도 종료: `expired`, `invalidated`, `rejected`; 재시험을 기다리는 상태는 `armed`로 남긴다.

- observed: 양 방향 구조 탐지 결과를 평가 시점별로 기록. 구조가 없으면 `no_structure`와 세부 사유를 남긴다.
- armed: 유효 구조·트리거·허용 가격·만료 시각을 고정. 아직 사용자 메시지를 보내지 않는다.
- triggered: 실제 관측으로 트리거 충족.
- qualified: 구조·목표 공간·비용·위험·현재가 유효성·발송 제한 통과.
- acknowledged: Telegram 수락 확인. 단말 수신이나 체결을 뜻하지 않는다.
- tracking: 최초 계획을 보존한 채 가격·구조 및 관리 이벤트 추적.
- unknown: 공백 등으로 결과를 알 수 없음. 0원 또는 무손실로 대체하지 않는다.

후보 수를 늘리려고 관찰 메시지를 진입 알람으로 세지 않는다. 추가 상태 메시지는 사용자 별도 요청 전에는 발송하지 않는다.

탈락은 단계별 첫 차단 사유와 평가한 모든 부가 사유를 함께 보존한다. 실행되지 않은 검사는 `not_evaluated`로 둔다. 순서에 따라 처음 걸린 필터만 집계하면 인과가 왜곡되므로 아래 실험과 함께 본다.

사유 예: `no_structure`, `trigger_not_crossed`, `expired`, `structure_broken`, `entry_too_extended`, `room_conflict`, `room_unknown`, `rr_insufficient`, `cost_unknown`, `risk_cap`, `cooldown`, `duplicate`, `native_gap`, `send_failed`, `send_ack_unknown`.

## 5. 재현 가능한 장부

기존 `lbank_entry_timing.py`, `lbank_performance.py`, 연구의 영속 장부·재생기를 확장한다. 운영 모형 손익 장부를 실제 거래 계정 장부로 바꾸지 않는다.

| 기록 | 키와 필수 필드 |
|---|---|
| source_events | venue/instrument, event/receive time, ingest sequence, 원본 해시, 봉 확정·단위·품질 |
| opportunity_events | event_id, anchor_id, 방향, 구조 계열, known_at, trigger, invalidation, expiry |
| decision_events | event_id, policy_version, commit/config hash, eval time, 입력 해시, state, gate vector, first_reject |
| frozen_plans | plan_id, E/S/T1/T2, 각 가격의 구조 근거, Q, 비용 가정, risk budget, 진입 허용 구간 |
| dispatch_events | plan_id, dedupe key, 요청/응답 시각, provider message id, 확정·불명·실패 상태 |
| outcome_events | plan_id, observed_at, TP/SL/변경 사유, 사용 가격·자료 해시, 결과 상태 |
| pairing | 공통 사건 ID, 비교 정책별 plan_id, matched/excluded/added/unmatched, 매칭 근거 |

시각은 UTC 원본 정밀도로 저장하고 화면만 KST로 표현한다. 같은 시각의 여러 입력은 ingest sequence로 구분한다. `available_at <= evaluated_at`를 검증한다. 명목 봉 마감은 수신 시각으로 대체할 수 없다.

event_id는 거래소·상품·구조 계열·방향·고정 anchor의 시각/해시로 생성한다. 전략 버전은 사건 ID와 별개다. 단순 표시 번호나 결과를 보고 사후 조정한 시간 창으로 거래를 합치지 않는다. 사건은 종료/만료 전까지 동일 ID이고, 새 구조 확인 뒤에만 새 ID가 된다. 장부 스키마와 이 ID 규칙을 버전 관리한다.

같은 입력에 대해 정책별 평가 상태·쿨다운·발송 이력을 독립 유지한다. 신규 정책의 추가 신호가 이후 쿨다운을 차지하는 효과도 실제 정책 경로 비교에 반영한다.

신호 기록과 발송 의도는 트랜잭션으로 보존한다. 수락 시간 초과는 불명 상태로 남기고 맹목적으로 재전송하지 않는다. Telegram 외부 전달의 완전한 exactly-once를 주장하지 않는다.

추가 분석 로그는 기존 거래 기록보다 낮은 우선순위로 용량을 제한한다. 원본 봉은 공통 저장하고 정책마다 복제하지 않는다. 연구 로깅 실패가 운영 감시 프로세스를 중단시키지 않도록 격리한다. 보존 기간·용량·아카이브 해시를 기록하고 분석에 필요한 구간은 비교 완료 전 삭제하지 않는다. 비밀키·개인 채팅 내용은 아카이브에 넣지 않는다.

## 6. 세 가지 비교를 실제로 수행하는 방법

### A. 어느 단계에서 탈락했는가

두 종류의 분모를 나눠 표시한다.
1. 입력 상태: 전체 관측·유효 관측·자료 누락·구조 없음.
2. 고유 사건 흐름: 구조 발견→트리거→목표/위험 통과→확인→발송 가능→실제 수락.

같은 봉의 반복 평가를 거래 기회 여러 건으로 세지 않는다. 전략별·방향별·변동성별로 단계 간 탈락률과 사유를 표시한다. “no_setup 766회”는 766개의 놓친 거래가 아니다.

### B. 같은 기회를 더 일찍 포착했는가

양 정책의 구조 anchor가 일치하면 공통 사건으로 대응한다. 정책 간 다른 구조는 억지로 매칭하지 않고 unmatched로 표시한다.
- 후보 지연, 확인 지연, 발송 요청 지연을 known_at 기준으로 각각 비교.
- 기존보다 몇 초 빠른지와 실제 진입가 차이를 함께 제시.
- 방향별 진입 악화량 = d×(E_new−E_old). 음수면 신규가 더 유리한 가격이다.
- 비교 가능한 시점의 공통 ATR로 거리 차이를 표준화. 서로 다른 시점의 줄어든 ATR로 추격 정도를 유리하게 바꾸지 않는다.
- 알람만 빨랐으나 구조 실패·손절이 늘면 개선으로 통과시키지 않는다.

### C. 제외·추가 신호의 이후 결과

공통/기존만/신규만/매칭 불가 네 묶음으로 모든 계획을 공개한다.
- 제외 신호: 회피한 손실과 포기한 이익을 모두 집계.
- 추가 신호: 추가 이익·추가 손실·미확정을 모두 집계.
- 공통 신호: 진입 시점 효과와 목표/손절 변경 효과를 분리.
- 실제 운용 경로의 합산에서는 **진입하지 않은 정책의 포지션 손익은 0**이 맞다. 반면 진입했으나 결과가 누락된 거래는 null이다. 둘을 혼동하지 않는다.
- 장벽이 없는 시간도 포함한 연속 구간을 사용한다. 두 정책 모두 포착하지 못한 기회는 독립된 공통 구조 탐지기의 사건 목록으로 보조 점검한다. 이것을 시장의 모든 변곡점을 잡는 정답 목록이라고 부르지 않는다.

출력 CSV의 필수 열:
`event_id, group, direction, anchor_known_at, old/new_candidate_at, old/new_confirm_at, old/new_entry, stop, target1, target1_basis, nearest_barrier, gate_reasons, tp1_before_sl, mfe_r, mae_r, outcome_status, net_pnl_model, data_limitations`.

## 7. 실험을 분리하는 순서

기존 capture를 대조군 B로 고정한다. 이미 여러 번 사용한 3개 신호 주변 자료는 개발·회귀 자료이며 새 검증 자료라고 부르지 않는다.

| 실험 | 단독 변경 | 확인할 문제 |
|---|---|---|
| E1 | 첫 재시험·조기 포착만 | 후보/시각 변화 |
| E2 | 구조 목표→허용 진입가 역산만 | 목표 현실성·기회 손실 |
| E3 | 확인 시 고정 대기를 근거 기반으로 바꿈 | 지연 감소와 거짓 확인 |
| E4 | 가까운 장벽 예외·추격 규칙만 | 손실 회피와 정상 기회 차단 |
| E5 | 초기 반전 경로만 | 추세 정렬 전 포착의 유효성 |

PR #21 묶음 결과는 별도 행으로 보존한다. 초기 진단에서는 같은 기존 자료로 각 단독 변경을 분석하되 승자를 고르는 성능 검증으로 해석하지 않는다. 개발 구간에서 조합 하나를 선택하고 파라미터·코드·자료 범위·검사 시점을 고정한 뒤, 사용하지 않은 연속 자료에서 그 조합을 B와 비교한다. 조합 상호작용은 조합 자체의 결과로 다시 검증한다.

실패한 실험을 삭제하지 않고 시도 수를 기록한다. 비교 결과를 보며 매번 문턱을 조정하면 새 버전으로 번호를 올리고 다음 검증 구간을 분리한다. 같은 holdout을 반복해서 통과할 때까지 사용하지 않는다.

## 8. 방향·목표·손익을 구별하는 평가

- 방향 1차 지표: 최초 TP1과 최초 SL의 선행 여부. 둘 다 미도달이면 시간 종료 또는 아직 진행 중으로 구분.
- 보조 방향 지표: 5/15/30/60분 비용 후 수익과 MFE/MAE. 주 지표는 평가 전에 고정하고 사후 가장 유리한 시간만 골라 보고하지 않는다.
- 목표: TP1/TP2 도달률·도달 시간·목표 근거·초기 위험 단위 목표 거리. 목표를 가까이 낮춰 도달률만 올린 효과를 드러낸다.
- 진입: 공통 사건의 가격·시각 개선과 초반 구조 실패율.
- 사용자 효용: 유효 자료 시간당 최종 알람 수, 알람 없는 구간 길이, 유효 기회 포착률, 비용 후 손익, 평가손익을 포함한 최대낙폭.

청산은 두 패널을 유지한다.
1. 원인 분리용: 동일한 고정 청산 정책·비용·위험 예산.
2. 운영 근접용: 실제 부분 익절·추적·경고 규칙을 동일 입력 이벤트로 재생.

초기 비교의 최대 추적은 6시간으로 고정하고, 운영 정책 TTL이 다르면 별도 열로 남긴다. 봉 안에서 TP/SL 순서를 모르면 더 세밀한 실제 자료로 해결하거나 상·하한/미확정으로 남긴다. 시작가가 손절을 넘은 경우 불리한 시작가를 반영한다. 거래량 없는 가격 접촉을 확정 체결로 취급하지 않는다.

MFE/MAE와 낙폭도 관측 해상도 한계를 기록한다. 종가만으로 계산한 낙폭을 장중 최대낙폭이라고 부르지 않는다. 끝나지 않은 거래를 분석 시점마다 패배/승리로 바꾸지 않는다.

## 9. ‘개선됐다’고 보고할 판정 기준

아래 수치는 **검증 전 제안하는 제품 허용 기준**이며 수익성에서 도출된 최적값이 아니다. confirmatory 실행 전 manifest에 잠그고 결과를 보고 변경하지 않는다.

| 항목 | 승격 조건 |
|---|---|
| 자료/재현 | 미래 정보 사용 0, 해시·중복·비교군 상태 검증 통과. 유효 시간과 제외 구간 전부 공개 |
| 경제적 개선 | 신규 비용 후 기대손익이 양수이고, 기존 대비 같은 위험의 순손익 차이도 양수. 불확실성 구간이 이를 뒷받침해야 함 |
| 방향·목표 | TP1-before-SL 개선을 확인. 평균 위험 대비 목표 순익을 낮춰 만든 도달률 개선만으로 통과 불가 |
| 진입 시점 | 공통 사건의 확인 지연 중앙값 개선, 느린 쪽 90백분위 악화 없음. 초반 손절·무효화 증가 없음 |
| 알람 효용 | 동일 유효 시간의 최종 알람 빈도 및 독립 구조 기회 포착률이 기존의 90% 이상. 10%는 제안 허용 폭이며 기존 빈도가 낮으므로 무조건 감소를 승인하지 않음 |
| 낙폭 | 같은 위험·비용의 최대낙폭이 기존보다 악화되지 않음. 해상도 부족 시 미확정 |
| 미확정 | 방향·성과의 미확정 비율 5% 이하를 기본 목표로 하되, 미확정 포함 보수적 범위가 결론을 뒤집으면 보류 |
| 운영 | 중복 발송·오래된 신호 재발송·저장 실패·실행 버전 불일치 없음 |

사건은 서로 상관될 수 있으므로 1분 반복 평가를 독립 표본으로 넣지 않는다. 신뢰구간은 세션/일 블록을 보존하는 방법으로 계산하고 블록 수·가정·민감도를 공개한다. 표본이나 블록 수가 부족하면 숫자만 생성해 유의성을 주장하지 않는다. 후보 선택에 쓰지 않은 검증 구간과 사전 고정된 한 번의 주 판정을 사용한다. 반복 확인으로 우연히 통과하는 시점에 멈추지 않는다.

종료된 고유 사건 30건은 **중간 자료 점검선**일 뿐 합격을 보장하는 최소 표본이 아니다. 정식 판정에 필요한 사건 수·블록 수는 개발 구간의 변동성과 최소 의미 개선폭을 사용해 실행 전에 정한다. 정보가 부족해 산정할 수 없으면 정식 승격 검사는 시작하지 않고 진단 결과만 보고한다. 며칠 경과 또는 시험 500개 통과로 자동 승격하지 않는다.

기존 또는 신규 알람이 0건인 구간에서는 비율 계산이 정의되지 않을 수 있다. 절대 건수·유효 시간·시장 사건 수를 보고하고 0으로 나눈 값을 개선률로 만들지 않는다.

기존 함수는 어댑터로 연결하고 계산 코드를 여러 경로에 복사하지 않는다. 대조군 출력을 해시/거래별 결과로 고정한다. PR #21은 미승격 상태로 두며 무조건 먼저 병합하지 않는다.

필수 회귀 항목:
- 오른쪽 확인 봉이 늦게 수신된 피벗의 조기 사용 금지.
- 양 방향 target/stop 비용 수식, 가까운 장벽·unknown·gap·틱/수량 경계.
- 같은 사건 반복 평가·재시작·표시 번호 재사용에서도 고유성 유지.
- 미확정과 미진입 0 손익의 구별, 같은 봉 TP/SL 순서, 부분 청산 비용 중복 방지.
- 알림 수락 불명·기록 재시도에서 중복 발송 위험 통제.
- 1h/4h 불일치·누락은 신규 하드 차단을 만들지 않음.
- 수신 지연·발송 지연·확인 대기 시간의 구별.
- 새 로깅 실패가 연구/운영 감시 전체를 중단시키지 않음.

## 11. 사용자 보고와 작업 범위

다음 보고는 “시험 몇 개 통과” 대신 대표 성공·실패·미확정 거래 카드, 전체 비교표, 단계별 탈락, 알람 없는 구간을 함께 제시한다. 좋은 사례만 선별하지 않는다. 원자료 부족은 정확한 누락 구간과 필요한 소스를 명시한다.

이번 산출물은 설계서다. 새 전략이 구현·배포됐거나 성능이 확정됐다는 의미가 아니다. 기존 455/467개 시험과 과거 비교를 이 문서 작성 때문에 반복하지 않았다. 크레딧을 아끼기 위해 다음 구현은 P0를 먼저 수행하고, 탈락·지연 원인을 확인한 뒤 P1/P2의 실제 변경 범위를 결정한다.
