# LBank 알람 성과 보고 보완 구현 — 2026-10-31

## 결론
운영 `feature/lbank-futures-monitor`의 `b4c7d94efb305c19cbe44f050c806440e19351a0`에서 별도 브랜치로 구현했다. 운영 병합·배포·알람 재개·주문·Telegram 수동 발송은 하지 않았다. 이 변경은 **앞으로 수집되는 모의 거래의 설명력과 비교 가능성**을 높이며 수익성 개선을 입증하지 않는다.

이전 로컬 수정 파일과 `fix/lbank-performance-audit-20261031` 원격 브랜치는 복구되지 않았다. 인수인계 문서를 근거로 필요한 범위만 재구현했다. PR 21·22·27은 계속 연구용 초안이고 병합하지 않았다.

## 구현

### 거래별 근거와 비용 장부
`lbank_performance_audit.py`에 가산형 SQLite 표를 추가했다.

- 최초 진입 계획을 거래 ID별로 동결한다. 새 표 도입 전 거래에 과거 근거를 만들어 넣지 않는다.
- 관찰 quote 기준 MFE·MAE·표본 수·최대 표본 공백을 저장한다. 이는 체결 경로나 진짜 봉내 고저가가 아니다.
- 정책별 부분 익절·종료 leg, 기존 비용 모형의 수수료·슬리피지·펀딩 준비율, 경고 적용/미적용/역순/공백 결과를 기록한다.
- 분류·확인·발송 차단 단계를 같은 시각에도 별도 저장한다.
- 완료 1분봉 안에서 손절과 목표가 모두 닿아 선후를 모르면 `censored_intrabar_order`로 제외한다. 손절 또는 목표가가 quote 사이에서 먼저 닿은 흔적도 검증되지 않은 체결로 확정하지 않는다.
- 읽기 전용 exporter는 거래별 행, 정책 쌍 비교, 청산일 기준 전체 거래 손익, 실제 보관 범위와 입력 DB 해시를 같은 SQLite snapshot에서 출력한다.

`research/export_performance_audit.py` 사용 예:

```bash
python -m research.export_performance_audit --db COPY.sqlite3 --day 2026-10-30 --output report.json
```

운영 DB를 직접 수정하지 않으며 입력 DB와 출력 경로가 같으면 중단한다.

### 누락 없는 탈락 사유와 보고
- `calculate_plan`이 표본 부족, 변동성 자료 부족, EMA 대비 과도한 진입, 재지지 후 과확장, 손절 거리, 비용 후 손실 오류, 목표 계산 불가, 관측 범위 밖 목표, 구조 장벽 충돌, 원본봉 장벽 충돌, 최소 수량 미달, 비용 후 손익비 미달을 각각 기록한다.
- 후보별 계획 사유를 분류 기록에 보존한다. 확인 단계와 발송 차단 단계도 독립 사건이다.
- 일일 보고는 전체 사유별 건수와 합계를 함께 보여 주며 개선·악화·동일·미확정 제외 쌍을 분리한다.
- 최대 90일은 보관 상한으로 표기하고 90일 백테스트로 표현하지 않는다. 공개 기법은 실제 보관 평가 시각과 자료 상태를 별도 표기한다.
- 보고서가 Telegram 한도를 넘으면 일일 보고에만 결정적으로 분할한다. 진입 알람 전송 방식은 바꾸지 않았다.

### 돌파와 눌림 독립 비교
`research/compare_entry_routes.py`는 오프라인 입력에서 같은 동결 박스의 첫 완료 5분 돌파와 이후 완료 1분 재지지를 독립 경로로 비교한다.

- 돌파 경로는 재지지를 기다리지 않는다.
- 재지지 경로는 같은 기회 ID·손절·목표·비용 모형을 쓴다.
- 양쪽 진입, 돌파만 진입, 재지지만 진입, 미진입과 선행 시간·진입가 차이·양쪽 결과 확정 시 순손익 차이를 구분한다.
- 1시간·4시간 방향은 참고 정보이며 탐지나 진입을 차단하지 않는다.
- 이 비교기는 운영 스케줄러 전체나 실제 체결을 재현하지 않는다.

### 구조 목표에서 허용 진입가 역산
검증된 연구 브랜치의 순수 계산 모듈 `lbank_structural_target_plan.py`를 재사용했다.

- 당시에 확인 가능했던 미돌파 피벗과 수신 시각만 사용한다.
- 실제 구조 목표와 기존 구조 손절을 고정한 뒤 비용 후 최소 손익비를 만족하는 최대 롱/최소 숏 진입가를 역산한다.
- 먼 2차 목표를 새로 만들지 않는다. 비교 시 두 물량은 같은 구조 목표로 계산한다.
- 수량 단위·최소 수량·최소 명목금액을 적용한다.
- 운영 호출은 `target_policy`를 전달하지 않으며 기능은 오프라인 비교용 주입으로만 존재한다. 기본 운영 경제·위험 조건은 그대로다.
