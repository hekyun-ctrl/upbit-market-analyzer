## 새로 확인한 원인과 근거

공식 프런트엔드의 chart adapter는 `h`를 volume으로 받아 종목에 따른 단위 변환을 적용합니다. 선형 종목의 코인 수량은 `volume × volumeMultiple`이며, 수신한 BTCUSDT의 배수는 1입니다. `i/h`가 OHLC 가격 범위에 놓이는 것도 모든 보존 원문에서 일치했습니다. 이는 이전의 "종목 배수만 알 뿐 candle 필드 연결을 모른다"는 정보 공백을 좁힌 실제 새 근거입니다. 다만 이 자료를 발행자의 명시적인 candle 단위·정정 계약과 혼동하지 않으며 전역 차단 값을 강제 해제하지 않았습니다.

공식 KLine 키 매핑에 확정 필드는 없습니다. `j`는 timeZone이며, `tradeTime=true`도 마감 전에 나타납니다. 현재 확보한 별도 5분 응답도 진행 중 스냅샷입니다. 따라서 raw5m를 받았다는 사실만으로 독립적으로 발행된 **확정** 5분봉의 과거 이력, 마감 후 정정 규칙, 최초 발표·수신 시각의 연속성을 검증할 수 없습니다.

CCXT의 현재 `fetch_ohlcv`도 `spotPublicGetKline`을 호출함을 다시 확인했습니다. 현물이나 다른 거래소 봉을 선물 원문 대신 사용하지 않았고, 실패했던 과거 봉 REST 경로를 다시 호출하지 않았습니다.

거래소의 공개 선물 1분/5분 이력 접근 명세, 확정·정정 규칙, 거래량 단위와 독립 발행 기준 확인이 필요합니다. 새로 확보한 코드·원문을 첨부할 수 있도록 [기술지원 질의](PROVIDER_REQUEST.md)를 구체화했습니다. 아직 타인에게 발송하지 않았습니다.

답변 확보 후 기존 importer의 source-dependent decoder와 원문→파생 상태·매 quote/poll의 연결을 검토합니다. 이후 기존 정책·손절·비용을 고정한 미사용 연속 구간 비교와 결과 판정을 수행합니다. 현재/예정 펀딩은 정산 이력을 대신하지 않으며, 자료가 없거나 미확정이면 수익·최대낙폭을 null로 남깁니다. 기존 개발 자료를 미사용 표본으로 재분류하지 않고 임의의 추가 표본 수·기간·진입 필터도 만들지 않았습니다.
