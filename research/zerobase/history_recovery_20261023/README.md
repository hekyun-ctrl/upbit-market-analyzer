# LBank 과거봉 회수 결과 — 2026-10-23

## 확보한 자료

운영 수집기의 `NATIVE_CANDLE_CLOSED` 로그에서 BTCUSDT USDT 무기한 선물의 실제 관측 5분봉 1,541개를 회수했다. 조회 범위는 2026-10-17 00:00 UTC부터 2026-10-23 11:20 UTC까지이며, 매일 나누어 최대 500행씩 조회했다. 각 응답은 500행 미만이었다.

- 봉 범위: 2026-10-17 13:15 ~ 2026-10-23 20:15 한국시간(마지막 시각은 봉 종료).
- 동일 중복 1행 제거. 충돌 중복 0, 잘못된 OHLCV/시각 0.
- 5분봉 최장 연속 398개, 마지막 연속 42개. 전체 범위 내 누락 271개.
- 누락을 보간하지 않았다. 450개 연속 준비 조건은 충족하지 못한다.
- 완전한 구간만 재집계: 15분봉 508개, 1시간봉 119개, 4시간봉 22개.
- 4시간봉 마지막 종료는 2026-10-22 05:00 한국시간이다. 현재 참고 정보로 오인하지 말 것.

이 자료는 실제 시장 관측을 복구한 것이지만, **5분봉 자체도 기존 수집기가 1분봉 5개를 합친 파생 봉**이다. 거래소에서 별도로 받은 독립 5분봉이 아니다. 원본 1분봉 행은 이번 로그에 없으며 거래량 단위도 아직 미검증이다. 원래 거래량·거래대금 숫자를 그대로 보존했다.

## 파일과 재현

- `candle_logs.jsonl`: 봉 로그만 추린 원문과 원래 로그 시각. 계정/발송/일반 운영 로그 제외.
- `BTCUSDT_5m_derived.csv`: 중복 제거한 5분봉.
- `BTCUSDT_15m_derived.csv`, `BTCUSDT_1h_derived.csv`, `BTCUSDT_4h_derived.csv`: 공백 없는 구성 봉만 재집계.
- `manifest.json`: SHA-256, 봉 수, 기간, 누락 구간, 독립성·단위·수익 검증 상태.
- `validate_export.py`: 로컬 오프라인 검사 및 CSV 재생성. 운영 엔진에 쓰지 않는다.

실행: `python research/zerobase/history_recovery_20261023/validate_export.py`

가격의 유한성·양수·OHLC 범위, 음수 거래량, 5분 경계, 로그가 봉 종료 뒤인지, 갱신 시각 범위, 중복 충돌을 검사했다. 이는 자료 형식·연속성 검사이며 전략 손익 또는 수익성 검증이 아니다.

## 직접 과거봉 조회 조사

공식 공개 차트 https://www.lbank.com/futures/btcusdt 는 로그인 없이 과거 차트를 표시했다.

해당 페이지가 불러오는 공개 코드
`https://www.lbank.com/static-client/lbank-front-trade/_next/static/chunks/pages/_app-b8e5abeec5ebd06c.js`
에서 다음을 확인했다.

- 운영 `cfdAddress`: `https://uuapi.rerrkvifj.com`.
- 공개 차트 과거봉 함수: GET `/cfd/query/v1.0/KLinelst`.
- 파라미터 이름: `instrumentID`, `exchangeID`, `startDatetime`, `count`, `type`, `isUsd`.
- 함수의 `isUsd` 값은 1이다. 나머지 인자의 정확한 호출 값과 시간 단위는 아직 검증하지 못했다.

직접 HTTP 조회는 HTTP 403 / `error code: 1010`을 반환했다. 시도한 요청값은 `instrumentID=BTCUSDT&exchangeID=Exchange&startDatetime=<조회 당시 Unix 초>&count=600&type=5m&isUsd=1`이며, **성공한 요청 형식이라고 볼 수 없다**. 접근 제한 우회, 브라우저 세션 인증 추출, 요청값 조합 반복을 하지 않았다. 공개 차트 메뉴에서도 내보내기 기능을 확인하지 못했다.

이전 문서의 `not open path` 조사보다 정확한 운영 호스트를 확인했지만, 독립 원본 과거봉을 다운로드한 것은 아니다. CCXT 현물 봉 또는 Binance 자료를 LBank 선물 봉으로 대체하지 않았다.

## 다음 작업과 운영 영향

1. 허용된 공식 과거봉 제공 경로 또는 정상적인 차트 내보내기로 원본 1분봉과 독립 5분봉을 확보해야 한다. 거래량 단위 및 두 주기의 OHLCV 일치 검증이 필요하다.
2. 확보된 연속 최신 자료를 운영에 넣을 때는 과거 주문/알림 생성이나 장부·잔고 초기화 없이 지표 이력만 준비하는 전용 절차가 필요하다. 기존 실시간 입력 경로에 과거봉을 그대로 밀어 넣지 않는다.
3. 이번 자료는 별도 검토 브랜치에 보관하며 운영 DB에 주입하지 않았다. 전략 조건·발송 설정·배포 변경 없음.
4. 1시간·4시간 방향과 자료 부족은 추가 진입 차단 조건으로 쓰지 않는다.
